## 怎么玩

### 方式零：直接打开单文件版（最省事）

```
dist/abyss-deck.html      # 约 0.81 MB，素材全部内联，零依赖
```

拷到手机/电脑上双击即玩，也可以直接发给别人（微信、网盘、群文件都行）。

### 方式一：开本地服务器用手机浏览器玩（推荐）

```bash
cd /sdcard/Download/roguelike
node server.mjs          # 默认监听 0.0.0.0:8765
```

然后在手机浏览器打开 **http://127.0.0.1:8765**

> 换端口：`PORT=9000 node server.mjs`

### 方式二：部署成网站（别人点链接就能玩）

把仓库推到 GitHub，`.github/workflows/deploy.yml` 会自动跑测试 → 构建 → 发布到 GitHub Pages。
另外在仓库 Settings → Pages 里把 Source 选成 **GitHub Actions** 即可。

任何静态托管都能用（Cloudflare Pages / Netlify / 自己的服务器…），因为整个游戏就是一堆静态文件。

## 装到桌面（PWA）

用 http(s) 打开游戏后，主菜单里有「**📲 安装到桌面**」：

- **安卓 / 桌面 Chrome、Edge**：弹出原生安装框，装完有图标、全屏、**离线可玩**
- **iOS Safari**：Safari 不支持自动安装，按提示点「分享 → 添加到主屏幕」
- 已经是独立窗口运行时不显示该入口

离线是靠 Service Worker 实现的：`sw.js` 会在安装时按 `precache.json`（构建期自动生成，
约 150 个资源）把精灵图、音效、字体一次性存进缓存，之后**断网也能完整游玩**。
`sw.js` 里的缓存版本号由 `npm run build` 按内容哈希自动盖戳（别手改），
这样每次发版都能让老用户的 SW 正常更新。

> ⚠️ **哈希覆盖"每一个预缓存资源的内容"** —— 这一点曾经是坏的：
> 旧算法只喂 `precache.json`，而它**只有文件名列表**，于是
> **只改素材内容（不改文件名）时版本号不变 → 浏览器不重新预缓存 →
> 用户看到的还是旧贴图**（Boss 立绘重画后就真踩了这个，线上换了图、
> 玩家却说"好像没变化"）。现在改任何素材/代码后**必须 `npm run build` 再提交**，
> 忘了会被 `V8` 段断言拦下。细节见[开发与维护指南](docs/开发与维护指南.md) §5。

> 单文件版本身就是全内联的，天然离线；只是 `file://` 打开时浏览器不允许注册 Service Worker，
> 所以那种情况下"添加到主屏幕"只是建个快捷方式，不会变成独立应用。

## 玩法

| | |
|---|---|
| **目标** | 从地牢一路打到深渊之眼，共 **4 层**，每层一个 Boss |
| **难度** | 同一批敌人会**随层数变强**：每上一层 **生命 +25%**、**攻击 +17%**（以第 1 层为基准）。第 4 层相当于 1.75 倍血、1.51 倍伤害 |
| **职业** | 铁誓骑士（护盾流/高容错）· 火焰法师（烈焰法术/能量饱和）· 暗巷游侠（低费/快过牌）· **寒冰法师（冰霜/冻结控场）** · **奥术法师（真理/多段连击）** · **炼金师（药剂/毒伤发育）** · **圣骑士（血牛/回复续航）** · 暗影刺客（叠易伤/一击必杀） |
| **战斗** | 每回合 **3 点能量**、抽 **5** 张牌。点数用光就结束回合 |
| **出牌** | 点手牌即可打出。需要选目标的牌，会先让你点敌人（点战场空白处可取消） |
| **长按卡牌** | 放大看清效果 |
| **看遗物作用** | **点一下遗物图标**就会显示它的效果（长按也行） |
| **用药水** | **点一下先看作用，再点一下才真的喝掉** —— 避免误触浪费；点开后图标会亮金边提示"待确认" |
| **回合结束** | 手牌全部弃掉，**护甲也会清空**（除非有「壁垒」） |

### 每一层的开场事件

**进入每一层时，都会先遇到一个开场事件**（学《杀戮尖塔》的 Neow）：
从 3 个选项里挑 1 个，拿到起手增益或做一次构筑调整，然后才开始探索这一层的地图。
选项**互斥、只能选一次**，而且中途关掉页面再回来还在原地，不会白拿或跳过。

| 层 | 开场事件 | 三个选项（大意） |
|---|---|---|
| 1 | 深渊入口 | 最大生命 +8 与 40 金币 / 一件普通遗物 / 回 25 血并 +4 上限 |
| 2 | 腐锈的岔路 | 60 金币与一瓶药水 / 失 10 血换一件遗物 / 回 35% 生命 |
| 3 | 深渊回廊 | 升级一张牌 / 移除一张牌 / 最大生命 +12 与 30 金币 |
| 4 | 深渊之底 | 失 8 血换一件**稀有**遗物 / 回 45% 生命并 +6 上限 / 升级**两张**牌 |

### 新手 / 老手

点「新的冒险」后会先问一句你是新手还是老手：

| 选择 | 去哪 |
|---|---|
| 🌱 **我是新手** | 用**铁誓骑士**直接开始，**0 分标准难度**（跳过难度与职业选择） |
| ⚔ **我是老手** | 先选[难度与增益](#难度系统)，再选职业（**职业按难度分逐步解锁**） |

**通关过一次之后就不再问了** —— 一律默认老手，直接进难度页。

### 难度系统

你可以自由勾选**难度规则**与**增益**，**最多 10 条**，最后的分值就是这一局的分：

- **难度规则每条 +9 分** —— 让你更难，但分值更高
- **增益每条 −4 分** —— 让你更轻松，但会拉低分值
- **什么都不选 = 0 分标准难度**（也就是原来的游戏）
- 分值只在**通关时**记入「通关最高分」—— 没通关的局不改变记录

**难度分还决定你能选哪些职业**（这是"越难越自由"的设计）：

| 职业 | 解锁门槛 | 职业 | 解锁门槛 |
|---|---|---|---|
| 铁誓骑士 | **0**（永远可选） | 炼金师 | 18 |
| 火焰法师 | 9 | 寒冰法师 | 27 |
| 暗巷游侠 | 9 | 奥术法师 | 36 |
| 圣骑士 | 9 | 暗影刺客 | 36 |

> 奥术法师与暗影刺客放在 36 分，是因为它们**叠起来会滚雪球**
> （真理让多段牌越打越多 / 易伤叠加后一击必杀）—— 用难度门槛限制，而不是削数值。

各条**独立生效**，所以可以只挑你认可的代价（比如"要钱不要命"：选涨价 + 选加血）。

### 状态效果

| 图标 | 名称 | 效果 |
|---|---|---|
| ⬆ | 力量 | 每次攻击 +N 伤害 |
| ✦ | 敏捷 | **每次获得护甲 +N** |
| ✸ | 易伤 | 每层使受到的**每一段**伤害 **+1**（自身回合结束 −1） |
| ▽ | 脆弱 | 每层使受到的**每一段**伤害 **+7%**，**最多 9 层**（自身回合结束 −1） |
| ↓ | 虚弱 | 造成的伤害**每层 −1 点**（分段招式每段各扣一次，**每段至少留 1 点**） |
| ☠ | 中毒 | 轮到它行动时掉 N 血（**无视护甲**），然后 **−2**（衰减最快，所以计价最便宜：1.5 点/层） |
| 🔥 | 点燃 | 同上，然后 **−1** |
| 🩸 | 流血 | 它**行动之后**结算，掉 N 血后**层数减半**（8→4→2→1，合计 15） |
| ❄ | 冰霜 | 集满后转化为 1 层冰冻（小怪 4 层、精英 7 层、玩家 4 层、Boss 9 层）。不自然衰减 |
| ❄ | 冰冻 | 怪物：跳过这次行动（意图保留）；**玩家：本回合能量减半** |
| ✹ | 荆棘 | 被近战攻击时反弹 N 点伤害 |
| ✚ | 再生 | 回合结束回复 N 点生命，然后 −1 |
| ◉ | 能量饱和 | 每回合能量上限 **+N** |
| ❖ | 洞察 | 每回合**额外抽 N 张牌** |
| ◈ | 抵挡 | 免疫接下来 **N 次减益** |
| ▣ | 壁垒 | 护甲不再于回合结束时消失 |
| ☯ | 强化 | 每回合开始获得 N 层力量 |
| ☠ | 淬毒 | 你施加中毒时**额外 +N 层** |
| ✚ | 血涌 | 你施加流血时**额外 +N 层** |
| ⛨ | 备战 | 下回合获得 N 点护甲 |
| ⚡ | 能量枯竭 | 下一回合能量 −N（结算一次后消失） |
| ◆ | 真理 | 每层使**多段**攻击/技能牌额外多打 1 次 |

> **易伤 vs 脆弱**（两个都放大伤害，但乘区不同，刻意不重合）：
> 易伤是**固定 +1/层/段**，对「多段小伤害」收益高；脆弱是**比例 +7%/层**，对「单发大伤害」收益高。

### 卡牌价值表

卡牌数值不是拍脑袋定的，而是按一张**价值表**折算后与"这一档的预算"对齐
（真源：`js/data/values.js`）。伤害/护甲/生命 = 1 点，能量 = 3，抽牌 = 5；
中毒 = 1.5（三种 DoT 里衰减最快，所以最便宜）/ 流血 · 点燃 · 虚弱 · 荆棘 = 2.5，敏捷 = 3.5，真理 = 5，冰霜 = 4.5（且只出现在 ≥2 费的寒冰牌上）；
力量 = 4（奥术法师 6）、易伤 = 4（奥术法师 5 / 暗影刺客 3.5）、再生 = 4（圣骑士 3.5）、脆弱 = 4（奥术法师 5）；
放大器型（淬毒/血涌/强化）= 6 + 2.5×N。

每档预算：1 费 5 / 6 / 7（普通/蓝/金），2 费 12 / 14 / 16，3 费 19 / 23 / 26。

- 逐张牌的审计表：[docs/卡牌价值审计.md](docs/卡牌价值审计.md)
- 按职业的设计说明：[docs/全职业牌组简介.md](docs/全职业牌组简介.md)
- 重新生成：`node tools/balance-report.mjs --markdown` / `node tools/class-report.mjs`

### 敌人一击伤害的配额（2026-10-13 收紧）

裸难度下，每只怪「最重的一次攻击」（多段算总和、不含它给自己叠的增益）被压进固定档位：

| 层 | 普通 | 精英 | Boss |
|---|---|---|---|
| 第 1 层 | 5~9 | ≤11 | ≤12 |
| 第 2 层 | 10~15 | ≤17 | ≤20 |
| 第 3 层 | 15~18 | ≤20 | ≤24 |
| 第 4 层 | 18~21 | ≤23 | ≤28 |

配套做了三件事，否则单靠压数值挡不住多段怪：

1. **多段招式一律 ≤2 段**：3 段招式在每层力量下吃 3 倍收益，是"多段统治"的根源。
2. **第 3 段起不再吃力量加成**（`POWER_STACK_CAP = 2`）：压总伤害只压住起点，压不住这个乘数。
3. **每层攻击成长 13% → 17%**：同一只怪会在多层出现（蛛后/巫妖在 2、3、4 层），
   13% 时它不可能同时满足两层的档位；17% 才能两边都落进去。

> 复核方式：`node tools/enemy-damage-report.mjs`（有超标会列出来，`--strict` 会以退出码 1 失败）。

### 敏捷对怪物到底生不生效？

**生效，但实战看不到是正常的。** 查证结论（真实引擎跑过）：
- 公式层、意图预告、实际结算**三处都会加** —— 怪物 3 层敏捷，加甲招式确实多 3 点。
- 但**敌人的护甲不吃层级缩放**（`gainBlock` 直接传原始 `blk`，只有 `damage` 才乘层倍率），
  所以它的数值变化比伤害更不显眼。
- **默认难度下怪物敏捷恒为 0**，唯一来源是难度规则「暴怒」。
- 而且只有 **19/43** 只怪有加护甲招式 —— 其余（深渊战士、深渊小鬼、深渊之喉…）
  **完全不受影响**，这正是"看起来敏捷没用"的原因。「暴怒」的描述已改成把这点写明。

### 第三 / 第四层专属敌人

深层原本只是复用前两层的怪（换个数值），玩家到第 3 层就会有"都见过了"的感觉。
这四只是后面加的，各自带一套**逼你换打法**的机制：

| 层 | 怪 | 机制 | 为什么这么设计 |
|---|---|---|---|
| 3 | 窃魂灯（小怪） | **能量掠夺**：每 3 回合夺走你 1 点当前能量 | 惩罚"攒着能量等大招"，它自己伤害很低 —— 威胁在节奏不在血 |
| 3 | 深渊祭司（精英） | **拖时间惩罚**：不断给全场加力量、往你牌堆塞诅咒，自己几乎不打人 | 反过来逼你**必须进攻**，和"高攻低血速战速决"的精英形成对比 |
| 4 | 虚空裂片（小怪） | **分裂**：血量跌到一半时裂成 2 个（各 40% 血，只裂一次） | 惩罚纯单点爆发；一波打死或用群攻就不会触发 |
| 4 | 深渊之喉（精英） | **护甲溶解**：每次出招**前**吞掉你一半护甲，然后再打 | 惩罚"叠满甲慢慢磨"，逼你一边防守一边输出 |

> 「护甲溶解」和「能量掠夺」的意图**气泡里会写明**（"出招前先吞噬你 50% 护甲"）——
> 它们的招式名里没有任何提示，不写清楚玩家只能靠挨打学会。

最终 Boss「深渊之眼」**不再召唤小弟**（原来会一次招 2 只深渊小鬼），
基础攻击也各降 1~2 点：去掉召唤后决战节奏更干净，玩家的注意力回到"挡哪一手、什么时候爆发"。

### 数据驱动

加内容基本只需要改 `js/data/` 下的文件，不用碰逻辑：

// 加一张卡
my_card: {

  art: 'sword_broad', dmg: 15, up: { dmg: 20 },
  text: c => `造成 <b>${c.dmg}</b> 点伤害。`,
  fx: [{ t: 'dmg', v: 'dmg' }],       // v 写字段名，升级后数值自动同步
},

### 测试覆盖（609 项，全绿）

- **数据层**：136 张卡的文案/效果字段/立绘、27 种敌人的招式/AI/立绘/召唤目标、
  37 件遗物的图标与钩子方法、遭遇战配置、各职业奖励池
- **逻辑层**：120 场随机对局（0 崩溃 / 0 死循环）、136 张卡 × 升级前后逐张实测可打出、
  200 个种子的地图全部可通关且房间类型齐全、敌人意图与实际动作一致性
- **贴图层**：自绘贴图的字符地图必须合法、**磁盘 PNG 必须与源码渲染结果逐字节相同**
  （手改 PNG 或改了源码忘记重新生成都会红）、只用项目原有调色板、
  四个 Boss 立绘互不相同且最终 Boss 有专属图、像素化规则的选择器真的覆盖到贴图元素、
  **四个职业立绘互不相同且刺客保留"可见面部+红眼"**（不能退回整张改色）、
  **SW 版本号等于全部预缓存资源内容的哈希**（改了素材忘记 build 会红）
- **难度系统**：10 条难度 + 10 条增益**逐条实际生效**验证（不是只查数据表有没有）；
  计分、上限 10 条、未通关不解锁、未知条目按 0 分、写进存档也能读回
- **DOM 层**：jsdom 真实加载页面，走完 菜单→选职业→地图→战斗→打完→结算；
  商店/事件/营火/宝箱/奖励 五个房间全部渲染 + 点击不崩；12 个事件 × 全部选项 × 4 职业
- **PWA / 预缓存清单**：清单必须**恰好等于**发布目录里的 Web 资源（不多不少）、
  每条都能在磁盘上找到、且不混入 `node_modules`/`.git` 等非运行期文件；
  必须按**码位序**排列（`readdir` 的顺序随文件系统变化，会让 `sw.js` 的版本哈希
  在 Windows/Linux 上不一致 —— 线上实测 `grave_cross` 与 `gravestone` 顺序相反）；
  只在本地开发用的 `js/dev-agent.js` 必须**同时**被 build 的排除清单、workflow 的
  rsync 排除、以及 `index.html` 三处挡住（漏一处线上 SW 就会请求到 404）
  （这条是补的：`buildPrecache()` 曾把 1156 个 `node_modules` 文件写进清单，
  而它们并不在发布产物里 → 每个访客首开白跑一千多个 404）
- **卡面文案长度门禁**：所有卡牌（含升级版）的文案都必须在 28 单位预算内 ——
  即**基准字号 10.5px 下就放得下**，不许依赖缩字。预算由真机标定，
  见 [docs/真机审计报告.md](docs/真机审计报告.md) §2–3
  （这条是补的：jsdom 没有布局引擎、量不到 `scrollHeight`，以前只能靠文档里的红线自觉）
- **存档往返**：地图坐标在 JSON 序列化前后都必须落在 0~1 范围内
  （这条是补的：之前 `layout()` 用对象引用找节点，读档后 52 个节点全跑到屏幕外）
- **地图语义**：200 个种子每张地图都必须**有且只有一个 Boss 节点**，且位于最后一行
  （这条也是补的：`add()` 的 `!n.type` 守卫把 Boss 类型静默吃掉了，导致打不通关）
- **地图不留死路**：最后一行**只允许有 Boss**，且任何非 Boss 节点都必须至少有一条出边、
  每条边都必须指向真实存在的节点 —— 走到没有后继的房间会永远卡在那里出不来
  （这条是补的：路径游走原本会一直走到最后一行，实测 **300/300 张地图**都多出普通节点，
  累计 753 个死路；而旧测试只验了"从起点能走到 Boss"，别的分支走进死角它测不到）
- **四层结构与强度曲线**：层倍率严格等于 `1 + 0.25×(层-1)` 生命 / `1 + 0.20×(层-1)` 攻击；
  同一个敌人在高层用**固定 RNG** 掷出的血量必须恰好等于 `round(原始 × 层倍率)`；
  四层 Boss 各不相同；**敌人意图预告的伤害必须等于实际打出的伤害**
  （跨 4 层 × 5 种状态组合：易伤 / 虚弱 / 力量 / 三者叠加）
- **选牌器（升级 / 移除）**：两条路径端到端跑通 —— 弹层按钮必须有文字、
  选卡进选中态、点「确定」后卡组**真的**升级/减少、再点一次已选中的牌能确认、
  没选卡点「确定」不会误删
- **战斗存档**：序列化 → 反序列化后敌人种类/血量、玩家血量、手牌内容、三个牌堆、回合数全部一致；
  真机上"关页面再进"实测连血量和能量都对得上
- **召唤归属**：召唤者死亡后小弟一并消失，且战斗能正确判定胜利
- **弃牌代价（飞刀）**：界面确实实现了 `requestDiscard`；玩家挑哪张就弃哪张；
  **取消弃牌也必须付出代价**（不能白赚）；界面没接回调时空转不了；手牌空时不卡死
- **存档版本兼容**：版本不认识的快照必须被**拒绝**而不是静默变成空战场 ——
  否则 `resume()` 会把"读档失败"当成"敌人全死"直接判玩家胜利（白送一关）；
  player/enemies 残缺、defId 全部无法解析等情况一律拒绝并改为重开这场战斗
- **监听器回收**：来回切 5 轮战斗/地图，window/document 上的监听器**不净增长**
  （修复前 5 → 30，修复后稳定 4）
- **敌人意图一轮只掷一次**：重复 `rollIntents()` 不再推进 RNG、不改动已定意图；
  读档续战沿用快照里的意图，**不会走出与"没关过"不同的未来**
- **伤害统计口径**：中毒 / 流血 / `loseHp` / 敌人自伤全部计入结算面板
  （敌人自伤算 `credit:'none'`，不记玩家的功劳）；单次统计不超过剩余生命
- **效果 DSL 与注释一致**：`dmgAll` 尊重 `hits`；玩家侧 `addCard` 真的能塞牌
  （旧代码只有敌人侧实现，照注释写卡会静默无效）；手牌塞不下时进弃牌堆且不超 10 张
- **状态标签**：标签上直接写出名称（虚弱/易伤/中毒…），长按看完整效果
- **遗物扩充与定值**：新增 9 件（27 → **36**）；每件的立绘、`mods` 键、`hooks` 方法
  都核对过"引擎真的会读"；且**不许做同类普通遗物的加强版**
  （超过参照值就必须带代价，否则 R3 段会红）
- **遗物负面效果已削减**：`贪婪之心 -6→-3`、`荆棘之心 -4→-2`、`战争号角 -8→-4`、
  `贤者之石 -10→-5`、`恶魔之眼 失5→失3`、`不朽之心 药水槽 -2→-1`
- **蓝色（罕见）卡提费**：「盾墙」「熔岩壁垒」2→**3** 费、「焦灼诅咒」1→**2** 费 ——
  只动"经量化对照确实明显强于同费同类普通牌"的那 3 张（R4 段用同一套价值模型盯着）
- **开场事件**：四层各一个、结构完整、**不会混进普通随机事件池**；
  进层先过事件再进地图，续战能正确回到事件（R5 段 + C 段端到端）
- **职业卡优先**：奖励池里本职业的专属卡权重是中立卡的 **3 倍**
- **费用图标按职业上色**：战士橙 / 法师粉 / 游侠蓝 / 刺客紫，非职业牌一律灰色；
  **战斗界面的能量球同色**；字色是按底色实测算过对比度的（最低 5.30:1，都过 AA）
- **怪物状态超过 6 个会折叠**：只留最重要的 6 个，其余收进「…」，点它弹出完整状态表
- **Boss 的第一次攻击打七折**：防止玩家刚进 Boss 房还没铺好就被一发带走
- **虚弱是固定扣减**：每层让**每一次**伤害 −1 点，分段招式每段各扣一次
  （3 段 × 4 点挨 2 层虚弱 → 3×2 = 6 点）。因为扣的是固定值，
  大伤害不会被压成 0（99 点挨 30 层虚弱仍打出 69 点），
  只有本来就很小段的攻击才会被削没 —— 这是刻意的曲线
- **斩杀（「暗杀」）**：伤害结算后，生命 ≤ 血量×25% 的目标**直接处决**并弹出「斩杀！」反馈
  （这个字段以前只写在卡牌数据里、引擎从未读取 → **斩杀一次都没触发过**）
- **毒死即结算**：敌人在怪物回合被毒死后**当场结束战斗**，不需要再点一次「结束回合」
  （旧代码只在"召唤物连带清场"时才判胜负，中毒分支走 `continue` 绕过了判定）
- **UI 同步刷新**：商店购买后金币减少且标题不被覆盖、营火休息后血条更新、锻造弹层显示升级后的数值
- **每层 Boss 立绘各不相同**：以前 `gargoyle`（3 层精英）与 `boss_gargoyle`（3 层 Boss）
  **逐像素完全相同**（`sprites.json` 里两者坐标都是 `[7,0]`，是同一张图）；
  `boss_demon` / `boss_gargoyle` / `gargoyle` 三张又共用同一套灰色调色板
  （`#8b9bb4 #262b44 #52607c #c0cbdc`），放大后难以区分；
  最终 Boss「深渊之眼」更是直接借用第 3 层「深渊之主」的图 + 色相旋转 —— 打到最后还以为在打同一只。
  现在四张 Boss 各有颜色身份（红魔眼 / 金冠石像 / 紫魔头 / 蓝深渊眼），
  精英石像鬼改灰色带角、与 Boss 彻底分开，最终 Boss 有专属立绘。
  （`boss_stone` 原本就是棕色造型、本来可区分，本次只是重画得更精致。）
  这几张改成**字符地图源码生成**（`tools/make-sprites.mjs`），可复现、可 review
- **像素贴图不再糊**：修掉一条**从未生效**的 CSS 规则（`img, .spr` 里的 `.spr`
  在实际 DOM 里根本不存在，贴图全挂在 div 的 `background-image` 上）——
  实测修复前 10 个贴图元素的 `image-rendering` 全是 `auto`，16×16 贴图被平滑插值糊掉；
  现在全局 `pixelated`，10/10 生效
- **药水 / 遗物交互**：遗物**单击**就显示作用（不再要求长按）；
  药水**两段式** —— 第一下弹说明且**不消耗**、第二下才真的喝掉；
  地图上的药水只给说明不会误用；切场景后气泡会被收掉（它挂在 body 上，不会随 #app 清理而消失）；
  药水数量从 0 变 1 时图标会刷新（旧代码用 `childElementCount` 判断，0 瓶和 1 瓶恰好都是 1 → 不重建）
- **运行期**：全程零未捕获 JS 错误

- **设计基准宽 430px**，CSS 里的尺寸都按这个宽度写
- 缩放到刚好铺满视口，**不缩小**（小屏 1:1），最大 3 倍
- 用 **`zoom` 而不是 `transform`** —— `zoom` 会触发重新排版，中文像素字体按目标字号光栅化、
  像素画按整数像素绘制，放大后不糊；`transform` 是把已经画好的位图拉伸，会糊
- **贴图本身也必须声明 `image-rendering: pixelated`** —— 只靠 `zoom` 不够：
  16×16 贴图若是用 `background-image` 放大，浏览器默认做平滑插值，边缘一样会糊。
  2026-10-12 修掉了这条（旧的 `img, .spr` 规则选择器写错了、从未匹配到任何元素）
- 不支持 `zoom` 的老浏览器（Firefox < 126）自动退回 `transform`，仍然铺满，只是略微柔化
- 飘字 / 长按气泡 / 提示条这几层不参与缩放，用真实屏幕坐标定位，字号按 CSS 变量 `--k` 放大

这样在两种环境下都能看清：

| 环境 | 视口 | 缩放 | 效果 |
|---|---|---|---|
| 正常手机浏览器 | 412×915 | 1.0× | 铺满 |
| 桌面模式浏览器（如 MIUI 开「电脑版网页」） | 980×1755 | 2.19× | 铺满，物理尺寸与手机一致 |

**手牌会自动叠放**：牌多时按可用宽度算错开距离，露出每张牌的 2/3 以上（费用、名字、立绘都看得见），
不用横向滚动；超过 8 张才会真的需要滑动。

**卡面文字自动适配**：描述放不下时逐档缩字号（`fitCardText()`）。
实测全部卡面在真机上零溢出、零缩字（含升级版）。
任何时候**长按任意卡牌**都能弹出放大版看完整效果。

**地图可以拖动**：`.map-wrap` 是真正的滚动容器（`overflow-y:auto` + `touch-action:pan-y`），
打开时会自动定位到「接下来能去哪」的那一批节点，上方留出余量；上下边缘有渐隐提示还能继续滚。

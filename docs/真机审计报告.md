## 3. 补上的门禁

在 `tools/test.mjs` 的 B 段（数据自洽性）里新增一条断言：

```
卡面文案长度都在预算内（≤ 28 单位，最长的 悔恨 是 25.2）
```

**阈值语义**：28 单位 = **必须在基准字号（10.5px）下放得下**，不许依赖缩字。
（29 单位起就会触发缩字 —— 字变小、可读性下降，应该是作者有意识的取舍，而不是不小心写长了。）

实测验证过这条门禁**真的会拦**：注入一张 43.2 单位的合成卡，测试立刻：

```
❌ 卡面文案长度都在预算内（≤ 28 单位，最长的 测试超长文案 是 43.2）
```

要写更长的文案时，请**先真机确认**，再有意识地调高 `tools/test.mjs` 里的 `TEXT_BUDGET`。
常量旁边写了完整的标定数据与推导过程。

## 4. 真机测量的一个陷阱（写新审计脚本时会踩）

`#stage` 用了 `zoom` 做整体缩放（见 README「界面自适应」），于是：

| API | 返回单位 |
|---|---|
| `getBoundingClientRect()` | **视觉像素**（已被 zoom 放大，÷ 2.19 才是布局值） |
| `clientHeight` / `offsetHeight` / `clientWidth` | **布局像素**（未缩放） |

**同一个元素上混用这两种单位会得到荒谬结论。** 我在标定时先写了一版混用的脚本，
结果「所有卡都超出 3.86 行」，而实际 0 张溢出 —— 因为 `getBoundingClientRect()` 量到的比
`clientHeight` 大 2.19 倍。

规则：**比较两个尺寸就用同一种 API**。量溢出用 `scrollHeight vs clientHeight`，
量位置用 `getBoundingClientRect` 但两边都用量出来的值。

## 5. 手机端的能力边界（对指南 §9 的修正）

指南 §9 写的是「手机端不方便跑 npm，所以 build→test→提交 以桌面端为准」。实际情况：

| 能力 | 状态 | 备注 |
|---|---|---|
| `node tools/build.mjs` | ✅ 可以 | Node 24 在容器里；依赖走 `/root/abyss-test/node_modules` 回退 |
| `node tools/test.mjs` | ✅ 可以 | **181 项全绿**（当时） |
| `npm ci` | ❌ 不行 | `/sdcard` 是 FAT 文件系统，**不支持符号链接**，npm 的 `.bin` 建不出来 |
| `git ls-remote` / `fetch --depth 1` | ✅ 可以 | 网络抖动时会失败，重试即可 |
| `git clone`（全量） | ⚠️ 不稳定 | 传输量大时容易 `GnuTLS recv error (-110)` |
| `git push` | ❌ 不行 | **容器内没有 git 凭证**（不是被墙，报错是 `could not read Username`） |

所以正确的表述是：**手机端能改、能 build、能 test，但推不上去。**

为此加了两个脚本：

- `tools/sync.sh pull|status` —— 拉取线上（优先 `git fetch --depth 1`，失败退 codeload tarball）
- `tools/handoff.sh` —— 把改动打成 `git diff` 补丁，交给有凭证的一端 apply + push
  （`sw.js` 的 `VERSION` 是构建期盖章的、跨机器必然不同，已排除出补丁）

**a. `sw.js` 的版本哈希跨机器不稳定** —— ⚠️ **本节结论已被桌面端推翻，见下方「桌面端复核」**

但「删掉某个敌人会让老存档打不开」这点仍在。

若想彻底解决，可选方案是**把敌人定义快照进存档**（name/sprite/hp/moves），
这样完全不依赖 `ENEMIES` 表。代价是平衡性调整不会作用到进行中的战斗。
**这是设计取舍，不建议我单方面改**，留给桌面端定。

> **桌面端答复**：同意这是设计取舍，**本次不动**。理由：现在这条路径已经是"安全失败"
> （要么正常恢复、要么重开这一场），不会让存档损坏或错乱；
> 而"快照进存档"会带来一个真实的坏处 —— 玩家打到一半的战斗不吃平衡性调整，
> 出问题时更难解释。除非将来真的频繁改敌人表，否则维持现状。

**桌面端复核（2026-10-12）——真凶不是 rollup，是文件系统的目录顺序**

~~`stampServiceWorkerVersion()` 对 `precache.json + index.html + css + dist/bundle.js` 算 SHA1，
其中 `bundle.js` 由 rollup 产出 → **依赖版本不同就得到不同哈希**。
实测：我用容器里的 rollup 算出 `abyss-4a79cc2ad5aa`，**和线上部署的完全一致**；
而仓库里提交的是 `abyss-b042b895292d`。也就是说 CI 是确定的，是**本地环境**与锁文件不一致。
影响：本地每次 build 都会弄脏 `sw.js`；另外每次部署会因为哈希变化白白失效一次全量缓存。
锁死 rollup 版本（确保 `npm ci` 与本地一致）即可。~~

手机端的观察（哈希确实不一致）是对的，但**归因错了**。桌面端实测：

| 检查 | 结果 |
|---|---|
| 锁文件里的 rollup | `4.64.5` |
| 本地实装 rollup | `4.64.5` |
| 结论 | **版本本来就一致**，所以不是依赖版本的问题 |

真正的原因：`buildPrecache()` 用 `walk()` 递归扫目录，而它按 `readdir` 的**返回顺序**追加 ——
这个顺序是**文件系统相关**的（NTFS 大致按名字，ext4 是哈希序）。

直接对证线上与本地的 `precache.json`（集合完全相同、149 项，**只有顺序不同**）：

```
线上(Linux): .../sprites/golem.png → grave_cross.png → gravestone.png → guard.png
本地(NTFS) : .../sprites/golem.png → gravestone.png → grave_cross.png → guard.png
                                     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 这两项换了位置
```

`grave_cross` 与 `gravestone` 只是恰好被这两种文件系统排到了相反的位置。
**集合一样、字节不同 → `precache.json` 变了 → SW 版本哈希必然不同。**
这跟 rollup、跟环境是否"干净"都无关，换台机器就会重现。

**已修**：`build.mjs` 改用 `sortedWalk()`（码位序 `sort()`，不依赖 locale），
`buildAssetMap()` 也一并改成有序 —— 后者决定单文件版里资源表的键顺序，同样需要确定性。
`tools/test.mjs` H 段加了一条断言盯住「清单必须按码位序排列」，
并已用"退回 `walk()`"的对照实验验证过它**真的会拦**（`第 35 项：anvil.png 应为 sprites.json`）。

顺带修掉一个手机端补丁**引入的新问题**（见 §9）。

## 9. 桌面端复核：dev-agent 改法漏了一处（会导致线上 404）

手机端把 `js/dev-agent.js` 从线上产物里摘掉，方向完全正确 ——
但它漏了一个地方：**`precache.json` 里仍然引用着 `./js/dev-agent.js`**。

`buildPrecache()` 的排除黑名单只有 `node_modules/.git/.github/tools/dist/_site` 和几个文件名，
`js/` 目录下的 `dev-agent.js` 照样会被扫进清单。而 workflow 的 rsync 已经把它排除出站点，
于是：

```
Service Worker 安装时按 precache.json 逐条 add()
  → ./js/dev-agent.js 在站点里不存在 → 404
```

这正是 H 段本来要防的那类问题（当年 1156 条 `node_modules` 也是同样的机制）。
桌面端用真实的站点组装语义复现了它：

```
站点里 js/dev-agent.js 存在: False
precache 引用但站点里没有的条目数: 1
   缺: ./js/dev-agent.js
```

**已修**：`build.mjs` 新增 `PRECACHE_SKIP_DEV_ONLY = new Set(['js/dev-agent.js'])`，
并且测试里把「build 的排除清单 / workflow 的 rsync 排除 / index.html 是否写死」
**三处绑成一条断言** —— 任何一处漏掉都会红：

| 故意制造的错误 | 测试的反应 |
|---|---|
| build.mjs 忘了排除 | ❌ 清单里没有多余条目 / 预缓存清单里不含只在本地开发用的文件 |
| workflow 忘了排除 | ❌ workflow 的站点组装排除了 js/dev-agent.js |
| index.html 又写死它 | ❌ index.html 不再写死调试代理 |

## 9. 第二轮：生命上限 / 体型 / 虚弱（手机端）

需求方（产品）报了 5 条，其中两条是**真 bug**，两条是**设计修正**，一条是**布局**。

### 9.1 职业基础生命上限 −15

骑士 82→67、法师 68→53、游侠 74→59。目的是降低玩家容错，让每一次挨打更疼。
`CLASSES[x].hp` 同时决定上限和开局血量，改一处即可。回归测试 S1。

### 9.2 提升生命上限时，当前生命同步增加

**改动前**：`addRelic` 里只有 `G.hp = clamp(G.hp, 0, G.maxHp)` —— 满血时拿到
「最大生命 +10」等于什么都没发生，遗物手感很差。

**改动后**：新增 `gainMaxHp(n)` 统一入口 —— 涨上限时**同步回血相同的量**；
降上限时只做夹紧，不会把人直接扣死。遗物（`addRelic`）和事件（`api.maxHp`）
都走这一条路径。回归测试 S2 / S3。

### 9.3 + 9.5 深渊之眼占地过大 / 召唤小弟溢出边框（**同一个根因**）

真机实测（980×1755，设计宽 447）：

| 场景 | 战场 y | Boss 立绘 | 结果 |
|---|---|---|---|
| 改动前 单个 | 176–551 | 溢出到 **y=164** | **向上顶穿 12px，压在药水条上** |

根因有两条，缺一不可：

1. **`boss_abyss`（深渊之眼）的 `body` 是 3.2 —— 全场最大**。
   76×3.2 = 243 布局px，在真机上接近 533 视觉px。
   而且它的 `brood`（召唤深渊）每 8 回合召唤 2 只小鬼，正好对应"召唤多次小弟"。
2. **战场本身没有任何尺寸约束**：`.field` 是 `flex: 1` 撑出来的，
   高度随屏幕变化；敌人一多或 Boss 一大就会顶穿边框，
   而 `.field` 没有 `overflow: hidden`，顶出去的部分就盖住了药水条。

**两条一起修**：

- **`body` 全部收敛**：深渊之眼 3.2→2.2、深渊之主 3.0→2.1、石像暴君 2.8→2.0、
  深渊魔眼 2.6→1.6、精英 1.7–1.9→1.5–1.6。测试 S4 加了一条数据门禁：**没有 `body > 2.2` 的敌人**。
- **敌人尺寸自适应**（`scene-battle.js` 的 `updateEnemySizing()`）：
  按战场可用宽高 + 预估行数算出精灵上限，写进 CSS 变量 `--spr-cap`；
  精灵尺寸是 `min(var(--spr-base), var(--spr-cap))`，
  所以**无论场上几个敌人、屏幕多矮，都不可能顶穿边框**。
  算法优先把敌人挤成一行，只有一行实在放不下才折行并按行高限制。
- **药水条等栏位强制置顶**（`.topbar/.relicbar/.potionbar { z-index: 6 }`）：

### 9.4 虚弱：从"每层 −25%"改成"每层每段 −1 点"

这一条改了两轮，值得记下来：

- **原始**：`if (weak > 0) d *= 0.75` —— 只判断有没有，叠 20 层也只 −25%
- **第一次修（PC 端）**：按层扣百分比 `WEAK_PER_STACK = 0.25` → 4 层归零
- **产品澄清后的最终定义**：**每层让「每一次伤害结算」−1 点**（固定值，不是百分比）

固定值模型自然解决了"4 层归零"的问题：99 点挨 30 层虚弱仍打出 69 点，
只有本来就很小段的攻击才会被削到 0 —— 这是刻意的曲线，不是 bug。

**分段招式每段各扣一次**（这是需求里点名的语义）：
3 段 × 4 点挨 2 层虚弱 → 每段 4−2=2，合计 6 点，**不是** 12−2=10。

计算顺序固定为：**先加力量 → 再减虚弱（都是固定值加减）→ 最后乘易伤**。
顺序写进注释了，挪动任何一步都会改变手感。回归测试 Q1 / Q1b / Q2 / Q2b。

#### ⚠️ 需要产品拍板的一个边界

固定扣减在**极端叠层**下仍然会把伤害压到 0。真机实测 20 点攻击：

| 虚弱层数 | 0 | 3 | 10 | **30** |
|---|---|---|---|---|
| 打出伤害 | 20 | 17 | 10 | **0** |

也就是说"无论什么攻击都为 0"这个现象**大幅缓解但没有根除** ——
现在需要「虚弱层数 ≥ 该段伤害」才会归零（20 点攻击要 30 层），
而百分比模型是「4 层封顶归零，再大的攻击也是 0」。

纯减法完全符合需求给的公式（每层 −1）。如果希望**彻底杜绝 0 伤害**，
可以再加一条下限「每段至少打出 1 点」，改动只有一行：

```js
d = Math.max(1, d);   // 放在减完虚弱之后、乘易伤之前
```

**这一条我没有擅自加**，因为它超出了"每层 −1"的字面定义，属于产品取舍。

### 9.6 顺带修掉的一个通用陷阱

`el()` 原本用 `Object.assign(node.style, {...})` 设置内联样式。
**`Object.assign` 写不进 CSS 自定义属性**（`--xxx` 会被静默忽略），
导致我第一版自适应尺寸完全不生效（4 个精灵尺寸一模一样）。
已改成对 `--` 开头的键走 `style.setProperty()`，并在注释里写明了原因。

### 10.6 顺带堵住的一类隐患：老存档引用了"已被删掉的数据"

排查时发现 `js/core/state.js` 的 `relicMods()` 长这样：

```js
for (const id of G.relics) for (const [k, v] of Object.entries(RELICS[id].mods || {}))
```

`G.relics` 存的是 **id**，而 `RELICS` 这张表是会被改的（删一件遗物、改个名字）。
一旦某个 id 从表里消失，**老存档里还留着它** → `RELICS[id]` 是 `undefined` →
读 `.mods` 直接抛异常。而 `relicMods()` / `relicHooks()` **每场战斗都会调用**，
所以表现是"更新之后一打开旧存档就崩"。

同一类裸读在渲染层还有十几处（`relicEl` 读 `.rarity`、商店 `relicPrice`、卡组视图等）。
**一处一处加防护不可靠** —— 总会有漏的（我第一版就只补了三处，核心的 `relicMods` 反而漏了）。

**治本的做法是在存档入口清洗**：`loadSave()` 里把 `G.relics` / `G.deck` 中
指向已不存在条目的元素直接丢弃，并 `console.warn` 出丢了什么。
再加上 `relicMods` / `relicHooks` / `addRelic` / `relicEl` / 商店价格这几处的兜底。

回归测试 U 段：往存档里塞 `__ghost_relic__` / `__ghost_card__`，断言读回来时已被清掉、
且正常卡牌没有被误删；再把脏 id 直接塞进 `G.relics` 渲染一遍地图与战斗界面，断言不抛异常。

> 这和指南 §7 待修的 #12（敌人按 `defId` 复原）是**同一类问题**：
> 存档里存的是"指向数据表的引用"，而数据表会变。
> 敌人那边已经有"数量不对齐就整体拒绝"的保护，遗物/卡牌这边现在也有了入口清洗。

## 11. 第四轮：敌人溢出复现与修复 / Boss 首击减伤 / 药水替换 / 职业重设计

### 11.1 「怪物又溢出屏幕」——复现到根因

截图里是「深渊魔眼 + 2 只吸血蝙蝠」，Boss 挂着 6 个状态（力量7 敏捷4 易伤9 虚弱5 中毒6 荆棘3）。
真机复现后量到了确切的数字：

| | 无状态 | 满 6 个状态 |
|---|---|---|
| Boss 上沿 | 372 ✅ | **−117**（跑到屏幕外） |
| 蝙蝠 下沿 | 821 ✅ | **1360**（跑到手牌区） |
| 溢出 | 0 | **上溢 1 / 下溢 1** |

**根因**：上一轮的 `updateEnemySizing()` 只按**精灵宽度**估算容器宽度，而状态标签是 `nowrap` 的 ——
`.enemy` 是 `flex: 0 0 auto`（按内容撑开），挂 6 个标签就把自己撑得很宽 →
一行挤不下 → 折行 → 总高从 660 变成 1400+，直接顶穿战场。

**两手一起改**：
1. **给敌人容器一个行宽上限**（`--enemy-max-w`，JS 按一行分几格算出来）——
   标签改为在容器**内部**换行，只长高不长宽，行数不变。
2. **迭代实测**：先按估算给一个 `--spr-cap`，然后**量敌人实际占用的高度**，
   超标就按比例缩，最多迭代 6 轮。这比任何公式估算都可靠 ——
   状态数量、标签文字长度、名字长短全都自动覆盖。

真机复测（宽屏 / 窄屏 × 多种编队）全部零溢出。

### 11.2 状态标签折叠（按需求改的交互）

内联最多 6 个状态，超出的收进一个「…」，点它弹出**完整状态表**（图标 + 名称 + 层数 + 逐条说明）。

留哪 6 个不是随机的：`ST` 表里每个状态加了 `pri` 权重，按重要度排序后取前 6。
中毒(95) > 力量(90) > 易伤(88) > 虚弱(86) > 敏捷(85) > 荆棘(80) … 靠后的（再生 40）优先被折叠。
这样"会决定生死的那几个"永远留在脸上。

### 11.3 Boss 第一次攻击减伤 30%

```js
if (d > 0 && atk && atk.boss && !atk.attacked) d = Math.max(1, Math.round(d * mult));
```

三个关键点：
- **只改 `calcDamage` 一处**：`intentOf()` 和 `enemyTurn()` 共用它，所以界面预告和实际伤害自动一致
  （这个项目有一条硬约束叫"预告不能撒谎"）。
- `attacked` 计数放在**挥出之后**：`intentOf` 在出招前调用，那时还是 0，看到的仍是减伤后的数值。
- **必须进快照**：漏了它，读档续战会把已经出过手的 Boss 当成"还没出过手"，白送一次减伤。

### 11.4 商店药水槽满时可替换

以前是 `toast('药水槽满了')` 直接拒绝。现在弹出选择器，**每一瓶都写出效果原文** ——
换哪瓶是构筑决策，看不到效果没法决定。

所以"槽是否满"必须在调用 `buy` **之前**判断；选完槽位再走 `buy` 扣钱。
真机验证：弹窗期间金币不变（999），选完 999→929，取消不扣钱。

### 11.11 灼烧状态 / 中毒衰减改为 -2 / 火焰法师职业特性（需求）

**灼烧（`burn`）** —— 新状态，与中毒同一套规则：

| | 触发时机 | 伤害 | 衰减 |
|---|---|---|---|
| 中毒 `poison` | 轮到它行动时 | N 点（无视护甲） | **-2** |
| 灼烧 `burn` | 轮到它行动时 | N 点（无视护甲） | -1 |

- 两者都在 `playerTurn` / `enemyTurn` 的同一处结算，写成 `for (const [dot, decay] of [['poison',2],['burn',1]])`，
  以后再加 DoT 只需往数组里塞一项。
- **负数问题**：1 层毒减 2 会算成 -1。虽然 `add()` 里有 `if (e.st[k] <= 0) delete e.st[k]` 兜底，
  但代码里还是显式写成 `-Math.min(n, decay)` —— 不依赖间接保护。
  回归测试 X1 专门覆盖"1 层毒跳完直接清除、字段不残留"。

> ⚠️ **平衡提醒**：中毒从 -1 改成 -2 是一次明显削弱。
> N 层毒的累计伤害从 ≈N²/2 降到 ≈N²/4（10 层：55 → 30 点）。
> 游侠是以中毒为核心的职业，这次改动对它影响最大，建议实机打两局感受一下。

**火焰法师职业特性「烈焰亲和」**：打出的**攻击牌**额外施加 **2 层灼烧**。

- 实现上做成 `CLASSES[cls].trait = { name, desc, sprite, mods }`，
  形状和遗物完全一致；`relicMods()` 把它和遗物、难度选项**一起聚合**。
  引擎侧只读 `this.mods.burnOnAttack`，完全不需要知道"职业特性"这个概念
  （和 `difficulty.js` 的设计一致）。
- **按牌算、不按段算**：多段攻击也只挂 2 层。否则法师的「万火齐发」（最多 8 段）
  一发就能叠 16 层，直接失控。回归测试 X4 专门断言"3 段的奥术飞弹只 +2"。
- 只对**攻击牌**生效；技能/能力牌不挂（测试 X4/X5 覆盖，且断言其它三个职业没有这个 mod）。

真机验证：连续 4 张攻击牌 → 灼烧 2 → 4 → 6 → 8，Boss 92 → 67 血。

**顺带修的**：「燃烧」这张火系卡原本挂的是**中毒** —— 一个叫"燃烧"的火系卡给敌人上毒
一直很违和，现在改挂灼烧。这也是法师唯一一张 DoT 牌。

## 12. 第五轮：新职业「寒冰法师」+ 冰霜/冰冻机制

### 12.1 冰霜 / 冰冻

两个新状态，走的是和中毒/灼烧同一套骨架：

| 状态 | 图标 | 规则 |
|---|---|---|
| 冰霜 | 手绘浅蓝靴子 `icon_frost` | **不自然衰减**。集满 → 消耗**全部**层数，转化成 1 层冰冻 |
| 冰冻 | 手绘浅蓝雪花 `icon_freeze` | 轮到它行动时消耗 1 层，**整个行动跳过**，意图保留到下一回合 |

- **冻结阈值**：普通/精英 **3** 层，Boss **5** 层（`freezeThreshold(e)`）。
- **转化写在 `add()` 里**：`if (k === 'frost' && e.st.frost >= threshold) { delete frost; add(freeze, 1) }`。
  多出来的层数直接丢弃 —— 需求原话是"消耗所有层数变成一层冰冻"。
- **冰冻检查必须在 `e.turn++` 之前**：turn 不推进，`pickMove(e.turn + 1)` 才会算出和这回合
  一样的意图，玩家看到的预告才不会变成假的。这是这套 AI 两段式设计的硬约束。
- **意图保留靠 `rollIntents(force, hold)`**：被冻住的敌人 uid 放进 `hold`，收尾重掷时跳过它。
  不落成持久字段，避免存档里多一个需要维护的状态。
- **DoT 照常结算**：冰冻剥夺的是它的"行动"，不是保护它免受毒/灼烧。
- **视觉**：`.enemy.frozen` 在 `.body` 上叠一层浅蓝半透明的 `::before`（`::after` 已被脚下影子占用）。

真机验证：冰霜 2 → 4 → **5 层瞬间变冰冻 1**（冰霜清零、滤镜出现、图标从靴子切成雪花）；
冻住后再过一个敌方回合 → 冰冻 0、**意图仍是 `⚔25` 没变**、**玩家血量 400 没掉**（确认跳过）。

### 12.2 寒冰法师（第 5 个职业）

- 生命 55（比火焰法师 53 略高一点 —— 控场职业打的是长线）
- 起始遗物 **寒霜核心**：`frostOnSkill: 1`
- 起始卡组：扔雪球×4 · 防御×4 · 寒冰箭×1 · 冰墙×1
- 专属牌 19 张，核心是"冰霜充能 → 冻住 → 让它少动一次"，唯一的爆发点是
  **碎冰**（对已冰冻目标额外 15 点）—— 奖励玩家把冻结循环跑起来。
- 费用图标 **浅蓝 `#a5ecff`**：选它是因为它同时满足两个条件 ——
  和深色字对比度最高（13.31:1），且与游侠的 `#5aa9ff` **色差最大（ΔRGB=101）**。

### 12.3 两个法师的基础牌都改成技能牌

| 职业 | 基础牌 | 类型 | 说明 |
|---|---|---|---|
| 火焰法师 | **火焰弹** | 技能 | 替换起始卡组里的「打击」 |
| 寒冰法师 | **扔雪球** | 技能 | 同上 |

**为什么要改类型**：职业特性的触发条件是"技能牌且对敌人生效"，
基础牌如果不是技能，那它永远触发不了特性 —— 等于每回合有一半的牌是"哑火"的。

### 12.4 火焰法师的特性变更（需求）

从「攻击牌挂 2 层灼烧」改成「**技能牌**挂 **1** 层灼烧」。

触发条件从"类型是攻击"换成"类型是技能且对敌人生效"，
并且按产品的补充说明：**群体技能也算**（`target: 'all'` 的技能对每个敌人都挂）。
自身增益（`target: 'self'`）不触发。

> 注意这是一次**明显的削弱**：火焰法师原本 12 张攻击牌都能挂灼烧，
> 现在只有技能牌能挂（改动前它的技能/敌方目标是 2 张，加上新增的火焰弹）。
> 实机打过之后如果觉得灼烧太少见，可以再把攻击牌加回来。

### 12.5 修掉的两处

1. **职业标记写死了四个职业名**：加寒冰法师时忘了加 `icemage`，
   导致它的费用图标一直是灰色。改成**查职业表**（`isClass`），以后加职业不会再漏；
   并补了一条门禁（Y1/Y2）：每个职业都必须有配色规则、每张专属牌都必须带职业标记。
2. **职业选择界面放不下第 5 个职业**：`.screen` 是 `overflow: hidden`，列表又没挂 `.scroll`，
   暗影刺客直接被裁掉。给列表加了滚动，并把职业卡压紧（立绘 56→46px、内边距收紧），
   真机确认 5 个职业一屏全部可见（短屏时可滚）。

### 12.6 寒冰法师立绘：按产品决定用换色

原计划是手绘一张独立造型的寒冰法师（因为 `sprites.json` 有一条"禁止 recolor"的守卫，
理由是"改色会产生同形而撞色的贴图"）。**产品明确要求直接换色**（"PC的提醒可以不管"），
理由是火焰/寒冰法师本就是**同一个"法师"形象**，同形是刻意的。

于是把守卫从"一律禁止"改成**允许清单制**：`RECOLOR_ALLOWED = new Set(['hero_icemage'])`。
守卫没有删掉 —— 任何新的 recolor 仍然必须显式登记，不能顺手加一个，
但这一对是被明确批准的。

换色只动红色族像素（`0.70 ≤ H ≤ 0.90` 那套改成 `H ≤ 12° 且 S ≥ 0.40`），
肤色 `#f7c282`、白胡子 `#c0cbdc`、深色描边 `#3f2631` 全部原样保留：
`#a63b32 → #3591ca`、`#d5655c → #66c4ff`。

## 13. 第五轮：数值价值表统一

### 13.1 价值表（产品给定，两轮调整后的最终版）

| 费用 | 普通/基础 | 蓝（罕见） | 金（稀有） |
|---|---|---|---|
| 1 费 | 5 | 6 | 7 |
| 2 费 | 12 | 14 | 16 |
| 3 费 | 19 | 23 | 26 |

**计价口径**（产品逐条确认）：
- 1 伤害 = 1 护甲 = **1 点**
- **所有状态层数一律 3 点/层** —— 包括中毒和点燃
- **冰霜是例外**，分两档（产品原话：「额外增加冰霜卡在**蓝卡**中的价值权重，
  例如蓝卡中最多允许一层冰霜+2点伤害/护盾，**三费卡正常算**」）：
  | 卡的类型 | 冰霜计价 | 上限 |
  |---|---|---|
  | 蓝卡（罕见），1~2 费 | **4 点/层**（补贴） | **最多 1 层** |
  | **三费卡（含金卡）** | **15 点/层**（正常） | 按预算 |
  | 普通卡 / 金卡（<3 费） | 15 点/层 | 按预算 |

  > 直接后果：**普通卡放不下冰霜**（普通卡预算 5 点 < 15 点），所以寒冰法师的
  > 冰霜牌只出现在**蓝卡和三费金卡**上。寒冰箭 / 刺骨 已从普通调为蓝卡。
  > **金卡可以有冰霜**（绝对零度 / 凛冬）—— 三费金预算 26 点，冰霜 15 点 × 全体 1.3
  > = 19.5 点，剩下 6.5 点还能带一份伤害，比蓝卡强得多。
- 抽牌 2 点、能量 3 点、斩杀 3 点、消耗 −2 点
- 条件加伤（ifBlock / ifVulnerable / ifFrozen）打 5 折
- 全体效果 ×1.3
- **共享总预算**：伤害 + 护甲 + 状态 + 其它机制一起分同一份额度
- 基础牌（打击/防御/火焰弹/扔雪球/影刺）统一按普通档

### 13.2 结果

工作前后「偏差 > 2 点」的卡：**89 张 → 30 张**。

剩下 30 张几乎全是**权力牌 / 开关牌**（壁垒=护甲不消失、影分身=每回合多抽、
火焰精通=每回合力量、烈焰引擎=能量上限、千毒=中毒加成）——
价值表只规定了伤害/护甲/状态，对「每回合型 / 开关型」效果，
模型的 3 点/层**低估了它们的真实价值**，所以显示亏模。这些是**模型局限，不是卡牌问题**，
刻意不改（按模型硬升会做出"每回合力量 +5""护甲不消失 ×8"这种破坏平衡的卡）。

### 13.3 过程中修掉的计价 bug

1. **`blockFromBlock` 忽略 mult**：固守 ×1 和 ×2 同分 → 计入 mult
2. **`blk` 字段被双算**：不屈/石肤这类「`blk` 其实是每回合护甲的层数」，被当成纯护甲牌
3. **多段攻击没除段数**：3 段牌会被按单段算，导致基础伤害被顶高
4. **先分配状态再分配伤害**：刃雨（2 费金全体伤害牌）被算成「1 伤 + 7 层中毒」，
   卡牌身份丢失 → 改成**状态只能吃伤害/护甲用剩的预算**
5. **无条件保底**：状态层数被压到 0 之后，卡面还在渲染「施加 0 层中毒」。
   保底必须**无条件**生效（写成 `if (n > 0)` 时，本来就 0 的字段保底不生效）。
   现在全卡池 136 张都无 0 层文案。

### 13.4 测试里写死的数值改成从数据读

锻造预览（G6）、斩杀触发（Q3）原本把 5 伤 / 25% 写死在断言里，
产品一调数值表就静默过期。现在都从卡片自身的 `dmg` / `exec` 反推。

> 教训：**凡是"期望值来自卡牌数据"的断言，都必须现场从数据读，不能抄数字。**

### 13.5 ⚠️ 一个差点导致错误结论的坑：真机验证被 Service Worker 缓存欺骗

改完这一大批数值、本地 build + 测试全绿后，真机抽检读到的**还是几个提交前的老数值**
（打击 6 伤而不是 5 伤、绝对零度还是"施加 3 层冰霜"）。差点据此判断"数值没生效"。

**根因**：`index.html` 注册了 PWA 的 Service Worker，它是 cache-first。
本地服务器虽然发了 `Cache-Control: no-cache`，但那是 HTTP 层，**SW 完全绕过它**。

**更隐蔽的一点**：先注销 SW + 清缓存**还不够** —— 当前页面内存里已经是旧 JS，
必须真正 reload 才会重新取。

**修法**：给 `server.mjs` 加一条 —— `/sw.js` 返回"自杀式"脚本
（activate 时清空所有 caches、注销自己、navigate 所有 client）。
只在本地开发生效，线上 GitHub Pages 照旧用真 `sw.js`。

**验证纪律**（写进错题本了）：真机验证前先确认
`navigator.serviceWorker.getRegistrations()` 为空、`caches.keys()` 为空；
改完代码要验证时走"注销 SW + 清缓存 + 强制 reload（带 cache-bust 参数）"三步，缺一步就还在读旧代码。

修好之后复验：SW 0 个、缓存 0 个、136 张卡的数值与文件逐字一致。

## 14. 第六轮：奥术法师 + 真理 + 战场溢出/出怪上限

### 14.1 新状态「真理」与新职业「奥术法师」

**真理（truth）**：本身没有直接效果，它的作用是**在引擎里当"多段加成"的计数器**。
每层让**本来就有多段**的攻击/技能牌额外多打 1 次（`effHits()`）。

- 只对 `hits > 1` 的牌生效 —— 单发牌不会因为真理变成多段，这是职业设定
  （"通过叠真理层数来进行多段连击"，和游侠"多打几张牌"区分开）。
- `dmg` 与 `dmgAll` 两条路径都走 `effHits`，群攻的多段也吃真理。

**奥术法师**：生命 54，起始遗物「真理之核」（`hitsPerTruth: 1`），
起始卡组 奥术飞弹×4 · 防御×4 · 法力飞镖×1 · 符文护盾×1，专属牌 19 张。

设计约束（产品要求）：**力量只出现在三费卡**。多段攻击会被力量**逐段**加成，
1 费多段牌带力量会直接失控。已加测试守住这条。

> 真理 5 点/层很贵，所以**1 费卡塞不下「真理 + 别的」**（1 费普通预算只有 5 点）。
> 带真理的牌一律排在 2 费：求真（1 费·1 层）、洞察（2 费·2 层）、万物归一（3 费·3 层）。

### 14.2 战场：溢出裁剪 / 出怪上限 / 死亡重排

1. **意图栏被裁**（产品报的 bug）
   复现：8 只正常；**10 只上溢 155px、只有 6/10 条意图可见**。
   根因是经典 flex 陷阱 —— `align-content: center` 在内容比容器高时会**上下同时溢出**，
   上排（Boss 常在这排）连同意图一起被裁掉，而且滚不到。
   修法：溢出时 JS 把 `align-content` 改成 `flex-start` + 敌人 ≥5 只切「拥挤模式」
   （意图/名牌/状态全压紧，优先保意图）+ `.field` 可纵向滚动兜底。
   复测：10 只 10/10、12 只 12/12、15 只 15/15（改前 6/10、8/12、8/15）。

2. **出怪硬上限**（产品要求）：`MAX_ENEMIES = 8` 放在 `spawn()` 这个唯一入口，
   任何召唤路径都绕不过去（`summon` 效果另有一条更紧的 4 只上限）。

3. **死亡后重排**（产品要求）：以前死怪只加 `.dead`（opacity:0），
   **节点仍占布局空间**，死一只剩下的也不会变大；`enemyBlockHeight()` 还会把死节点量进去，
   尺寸被白白压缩。现在淡出 380ms 后真从 DOM 移除 + 重排。
   真机：死 2 只后 DOM 节点 8→6、精灵 62px→74px。

### 14.3 bug：怪物「敏捷」在意图预告里不生效

`intentOf()` 里伤害走了 `calcDamage`，但**护甲直接取 `def.blk` 原始值**，没走 `calcBlock`。
后果：怪物有敏捷时，加甲意图显示原始值、实际却多加（有时还要再乘 frail）——
和项目反复强调的「预告不能撒谎」是同一类 bug。

修法：`if (def.blk) out.blk = this.calcBlock(def.blk, e);`
顺带把护甲数字显示到意图上（原来只在长按气泡里）。
真机：16 → 4 层敏捷 → 20 → 有 frail → 15，**预告与实际逐点相等**。

### 14.4 其它（产品要求）

- **同职业内完全重复的牌拉开区分度**：数值表落地后 1 费普通档只有「5」一个值，

- **状态权重**：DoT 4 点/层、虚弱 4 点/层、其余 5 点/层。
- **配色**：骑士 浅橙 `#ffc06b`、火焰法师 红 `#ff5a5a`、奥术法师 浅紫 `#d8b4ff`。

  但价值表落地后蓝卡预算本就高于普通牌，参照物还可能是效用牌（苹果比橘子）。
  现在直接比价值表预算 —— 这才是真正要守的不变量。

## 15. 第七轮：流程重排（难度→职业）+ 职业解锁 + 卡池去重

### 15.1 流程改动（产品要求）

**难度页提到职业页之前**，职业按难度分解锁：

```
新手（没通关过）→ 直接骑士开局，**跳过难度与职业选择**
```

| 职业 | 解锁门槛 | 理由 |
|---|---|---|
| 铁誓骑士 | 0（始终可选） | 新手默认 |
| 火焰法师 | 9 | 机制直观 |
| 暗巷游侠 | 9 | 机制直观 |

> 产品对「力量 + 多段」的处理是**用难度分解锁来限制**，而不是削数值
> —— 奥术法师叠起力量后连击次数会指数级放大，所以放到 36 分档。

真机验证：
- 新手点开始 → 职业 `knight`、**既不在难度页也不在职业页**，直接进第 1 层
- 老手点开始 → 先进难度页；选完 → 职业页 6 张卡，0 分时只有骑士可选，
  其余 5 个置灰并写明「🔒 需要 9/9/27/36/36 难度分」，顶栏显示当前难度分
- 4 条难度（36 分）→ 全部解锁，且真的能选进去（难度选择被带进本局）

### 15.2 卡池去重（产品游玩时发现）

两条不同的重复：

1. **防御（基础牌）= 符文护盾（奥术法师）** —— 都是 1 费 5 甲、升级后都是 8。
   基础牌是所有职业共用的，所以「某职业自己的牌」和基础牌撞车也算重复。
   符文护盾改成「3 甲 + 下回合 2 甲」（总额仍是 5 点预算）。
2. **秘法齐射（2 费蓝）= 公理（2 费金）** —— 都是 4 段 ×4、升级后都是 4 段 ×5，
   完全一样；而且 2 费的秘法齐射和 3 费连击牌性能也拉不开。
   秘法齐射降到 3 段（12 点），把「金卡更强」拉开。

**顺带修掉判据本身的一个漏洞**：我第一版查重正则**漏了 `hits` 字段**，
于是「2 段 ×2」和「3 段 ×2」被判成同一张 —— 该抓的反而没抓到（秘法齐射就是这么漏过去的）。
现在的判据带上 `hits`，并且**同时比升级前后**（升级后撞车一样要拦）。
口径也修正为「职业可用池 = 专属牌 + 基础牌」——
只按 cls 分组会漏掉「基础牌 vs 该职业自己的牌」这一类。

回归门禁：任何职业的可用池里出现两张完全同形同值的牌就报错（当前 0 组）。

### 16.1 新状态「流血」（游侠的职业 DOT）

| | 中毒 / 点燃 | **流血** |

（这条一天内被调过三次：+20% → +15% → +20% → **+13%**。）

### 19.5 顺手修掉一个 flaky 测试

补丁自检里偶发挂了「有结束回合按钮 / turn 0 -> 0」，重跑三次全绿 —— 是**时序敏感的 flaky**。

根因：测试打出一张牌后用固定 `sleep(900)` 去找结束回合按钮，
但**打出的牌如果要点目标，界面会切进"选目标"态，那个按钮在这期间是不存在的**。
（测试自己前面其实已经意识到会进选目标态，后面却还是直接找按钮。）

改成等待式：先等到"按钮出现**或**出现可选目标"，若在选目标态就先把目标点掉。
连跑 3 次全绿。

### 19.6 ⚠️ flaky 测试的最终定位（第一次没修干净）

第一次只当成"时序敏感"，把固定 `sleep` 换成等待式就收工了 —— **结果补丁自检又挂了一次**。
才认真查，发现是**两个原因叠在一起**：

1. 打出的牌如果**需要选目标**，界面会切进"选目标"态，结束回合按钮在那期间**不存在**（第一次修的就是这个）。
2. **更隐蔽的**：那一段测试跑在 `weak` 弱怪的战斗里，**一张牌就可能把怪打死** →
   战斗直接结束进结算界面，于是按钮和手牌都没有了（表现成 `turn 0 -> 0`）。
   测试其实**依赖了上一张牌的副作用**，而这个副作用不确定。

最终修法：把"结束回合 → 敌人行动 → 回到玩家回合"**单独开一场精英战**（血厚，一轮打不死），
不再依赖上一张牌的副作用；全部改等待式。**连跑 5 次全绿（546 项）**。

> 教训：偶发红必须查到底。它的真正代价不是"偶尔红一次"，
> 而是**让真正的回归淹没在噪声里** —— 下次看到同样的红就会当成"又抽风了"。

# 开发与维护指南

> 这份文档是接手/改动本项目时的**第一入口**。README 面向玩家，这里面向改代码的人。
> 内容基于对源码的逐文件阅读 + 在本机真实跑通 `build` / `test` + 线上站点实机点测。
> 凡未能确认的推断都显式标注「未确认」，不要把推断当结论用。

---

## 0. 三分钟上手

```bash
npm ci                # 安装依赖（jsdom + rollup）
npm run build         # 必须：产出 dist/bundle.js 与 precache.json
npm test              # 984 项
npm run build:single  # 可选：产出 dist/abyss-deck.html（素材全内联）
npm run serve         # 本地起服务，手机同局域网可访问 http://<电脑IP>:8765
```

**顺序不能反**：`dist/` 是 `.gitignore` 的，`tools/test.mjs:50` 直接读 `dist/bundle.js`，
所以**没先 build 就 test 必然 ENOENT**。CI 里也踩过这个坑（见 §7）。

改了 `js/` 或数据文件后，**每次都要重新 `npm run build`**，否则测的还是旧产物。

## 1. 架构与数据流

```
data/  纯数据（无逻辑）      cards / enemies / relics / potions / events / classes
  ↓
core/  引擎（不碰 DOM）      battle(战斗) · state(全局状态+存档) · map(地图生成) · util · audio
  ↓
ui/    场景（无框架，直接操作 DOM）
                            main(路由) · scene-battle · scene-map · scene-rooms · scene-menu · widgets
```

**关键约定：`core/` 绝不 import `ui/`**。战斗引擎想跟界面说话，一律通过 `opts.view` 上的回调
（`battle.js` 里满是 `this.view.onDamage?.(...)`），所以引擎可以在 jsdom 里裸跑——测试正是这么做的。

场景切换只有一条路：`main.go(name, ...)`（`js/main.js:20`）。每个 `sceneXxx()` **同步返回一个 `.screen` 节点**，
`go()` 负责 `clear(#app)` → append → rAF 里 `fitAllCards()` → 非菜单类场景 `save()`。没有虚拟 DOM，没有 diff。

## 2. 一个回合到底发生了什么（改战斗必读）

顺序是**语义的一部分**，挪动任何一步都会改变游戏行为。

**`playerTurn()`**
1. `turn++`
2. **清空护甲**（除非有 `barricade` 壁垒）—— 注意：**在中毒之前**
3. 结算玩家中毒（无视护甲掉血）→ 层数 −1 → 判死
4. `berserk_dmg` 自伤 → 判死
5. 遗物钩子：`undying`/`block_next` 加甲、`ritual` 加力量
6. 回满能量（3 + 各种修正，首回合另有 `firstTurnEnergy`）
7. **手牌全部进弃牌堆** → 抽 5 张（+修正）
8. `turnStart` 遗物钩子 → `rollIntents()`（决定敌人下回合意图）→ 同步界面 → 存档

**`endTurn()`**
1. 手牌里 `endDmg` / `curse_regret` 的反噬伤害
2. 手牌进弃牌堆
3. `tickEnd(玩家)`：`vulnerable` / `weak` / `frail` 各 −1
4. `regen` 回血后 −1
5. `turnEnd` 遗物钩子 → 存档 → `checkOver()`
6. 进入 `enemyTurn()`

**`enemyTurn()`** 遍历**进入那一刻的存活快照**（所以当回合新召唤的小怪不行动）
1. `e.turn++` → 清空敌人护甲（同上，除非 barricade）
2. 结算敌人中毒 → 判死则跳过
3. 执行**已预定**的 `moveId`：护甲 → 伤害（含多段 `hits`）→ `selfDamage` → `fx`
4. `tickEnd(e)` → 同步 → 判玩家死 → `checkOver()`

全部敌人行动完 → `rollIntents()` 预定下一轮 → 回到 `playerTurn()`。

### 意图为何总是准的
`pickMove` 用 `e.turn + 1` 计算，`enemyTurn` 只读预先存好的 `moveId`。
**所以"敌人头顶显示的意图"和它实际做的事必然一致**——改 AI 时不要破坏这个两段式。

### 死亡与召唤
- `damage()` 内 hp ≤ 0 → `kill()`；玩家死 → `endBattle(false)`
- 敌人死 → 把 `summonedBy === 该敌人` 的小弟**一并杀死**（避免 Boss 与小弟同归于尽时卡住判定）
- 场上敌人上限 **4 个存活**

## 3. 效果 DSL

卡牌用声明式效果描述，由 `resolve()` 解释执行，共 **21 种** `t`（真源：`battle.js` 的 `resolve()` 与 `cards.js` 顶部注释）：

```
dmg(带 hits) · dmgAll · dmgBlock · dmgPoison · dmgBleed · detonate
dmgPerHand · dmgPerPlayed · dmgPerEnergyMax
block · blockFromBlock · draw · energy · heal · loseHp
buff · debuff · debuffAll · gold · addCard · discard
```

```js
fx: [{ t: 'dmg', v: 'dmg', hits: 'hits' }]
```

`v` 可以是**数字**，也可以是**卡牌字段名的字符串**——结算那一刻才从卡实例上取值。

条件字段写在 fx 条目本身：`ifBlock` / `ifVulnerable` / `ifFrozen` / `ifLowHp` / `execute`。
**每一个都必须被引擎真的读过** —— `ifBlock`、`ifLowHp`、`execute` 都出过"只写在数据里、引擎从不读"的事故（卡面撒谎）。

**升级（`up`）为什么不用改 `fx`**：`makeCard()` 用 `Object.assign(c, base.up)` 覆盖实例字段，
`fx` 里写的是字段名，所以数值自动跟着升级走。这是这套 DSL 最省事的地方，加卡时请保持这个风格。

**敌人的效果是另一套解析器**（`resolveEnemyFx`），共 **9 种**：
`buff / buffAll / debuff / healSelf / block / summon / addCard / drainEnergy / eatBlock`。
敌人招式另认 `preFx`（出招**之前**结算，例如「吞噬甲胄」先吞一半护甲）、`selfDamage`、`hits`。
**两套不通用**，别把玩家的 `t` 写进敌人 `moves`。

## 4. 加内容：确切的步骤

> 共同前提：立绘名必须**同时**满足 ①`assets/sprites/<名>.png` 存在 ②`assets/sprites.json` 里有同名键。
> 改完记得 `npm run build`（刷新 `precache.json`），否则测试 H 段会失败。

### (a) 加一张卡牌 —— `js/data/cards.js`

必填：`name` · `cls` · `type` · `rarity` · `cost` · `target` · `art` · `text(c)` · `fx[]`
可选：`up{}`（升级覆盖同名字段）· `exhaust` · `unplayable` · 以及被 `fx` 用字符串引用的数值字段

```js
my_card: {
  name: '裂空斩', cls: 'knight', type: 'attack', rarity: 'rare', cost: 2, target: 'enemy',
  art: 'sword_broad', dmg: 15, up: { dmg: 20 },
  text: c => `造成 <b>${c.dmg}</b> 点伤害。`,
  fx: [{ t: 'dmg', v: 'dmg' }],
},
```

**测试会挡住的**：`id` 必须等于键名；`text` 升级前后都不能为空；`fx` 里字符串值必须是卡上真实字段；
`art` 必须在 `sprites.json`；卡牌总数 ≥ 50；**每个职业 × {common, uncommon, rare} 的奖励池 ≥ 3 张**。

**测试挡不住的坑**：造新的 `rarity` / `type` 字符串不会报错，但 `RARITY` / `TYPE_LABEL` 查不到 →
边框静默回退成 common、类型标签变空白。

**文案长度红线**：卡面字号从 10.5px 逐档降到 8.5px，再放不下就**直接裁字**。
实测现有 130 条文案最长 27 字、均值 15.3。**≤ 27 字安全**，30–36 字需要实机确认，> 36 字基本会裁。
`.ctext` 里必须包一层 `.ctext-in`；带 `<b>` 的 HTML 直接塞进 flex 容器会把文字拆行、卡高爆掉（源码有警告注释）。

### (b) 加一种敌人 —— `js/data/enemies.js`

必填：`name` · `sprite` · `hp:[min,max]` · `act` · `moves{...}`，外加 `ai(e,turn,rng,B)` 或 `pattern`
可选：`elite` · `boss` · `body`（体型倍率）· `tint`（CSS filter）

`act` 只是**这套数值的基线层**，不代表它只能在那层出现 —— 整张敌人表被所有层复用，
出场强度由 `actScale(层)` 再乘一遍（**每层 +25% 生命、+17% 攻击**，相对第 1 层；真源是 `ACT_HP_STEP` / `ACT_ATK_STEP`）。
所以：给第 4 层写新敌人时，数值要**照第 4 层的量级**给（它会再吃 1.6 倍攻击）。

**最容易被漏掉的一步**：敌人必须**手动**登记进 `ENCOUNTERS[act]` 的 `weak/strong/elite/boss` 里，
否则它**永远不会出现，而且测试不报错**（测试会核对"表里引用的 id 都存在"，
但不会核对"每个敌人都被用上"）。

**加层数**：改 `enemies.js` 的 `TOTAL_ACTS` 并补上 `ENCOUNTERS[TOTAL_ACTS]`。
`main.js` 的 `pickEncounter` / `afterRoom` 都读这个常量，不会再出现"第 4 层取不到遭遇战表"。
测试硬编码了 `TOTAL_ACTS === 4`，改层数时它会提醒你同步更新文档。

### (c) 加一件遗物 —— `js/data/relics.js`

必填：`name` · `sprite` · `rarity` · `desc`（字符串）+ `mods{}` 或 `hooks{}`

`mods` 的键必须被引擎真正读取（`maxHp` / `energyPerTurn` / `startBlock` / `shopDiscount` / `battleGold` …）。
**这条没有测试保护**——写错键名 = 遗物静默无效。`hooks` 里的方法名有测试核对（必须存在于 `battle.js`）。

**这些键分散在三处读，排查时别只看 `battle.js`**：

| 键 | 读取位置 |
|---|---|
| `maxHp` / `potionSlots` | `core/state.js` 的 `addRelic()`（**获得时**一次性生效） |
| `energyPerTurn` / `drawPerTurn` / `startBlock` / `startStrength` / `startDexterity` / `startThorns` / `startPoisonAll` / `startDebuffAll` / `startHeal` / `startLoseHp` / `firstTurnEnergy` / `firstTurnDraw` | `core/battle.js`（战斗内） |
| `cardBlockMult`（**卡牌**护盾 ×N，向上取整） / `vulnOnAttack`（费用 ≥1 的攻击牌命中后挂易伤） | `core/battle.js` 的 `gainBlock({fromCard})` / `playCard()` |
| `royalPath`（威望→太子→登基） / `debtSystem`（债务机制） / `debtBonus`（施加债务 +N） | `core/battle.js` 的 `checkRoyalPath()` / `playCard()` / `add()` |
| `battleGold` / `shopDiscount` / `cardChoice` / `healAfterBattle` | `ui/scene-rooms.js`（奖励、商店）/ `battle.js` 的 `endBattle()` |

> ⚠️ `cardBlockMult` **只作用于卡牌产出的护盾**：遗物（`startBlock`、钉刺长靴、静滞护符）
> 和药水都不算。判定靠 `resolve()` 传的 `{ fromCard: !!ctx.card }` —— 药水走同一个
> `resolve()`，但 `ctx.card` 是 null。改这块时别把药水也算进去。
>
> `healOnBigHit`（单次大伤害回血）已随「圣誓」改版**删除**：没有遗物再用它，
> 留着就是"声明了却没人读"的键。遗物回血现在只有 `healAfterBattle` 一处。

### 「死神」的债务（2026-10-17）

`debt` 是**卡牌字段**（与 `bonus` / `exhaust` 同类），不是 fx 条目：

- 由 `playCard()` 在 fx 结算**之后**统一施加，**只在 `debtSystem` 开启时生效**
  （否则别的职业拿到带 `debt` 的牌就能白嫖）。
- 计价在 `values.js` 的 fx 循环**之外**补一笔（1 层 = 1.5 点），群攻牌按 `ALL_MULT` 放大。
- 裁决点在 `enemyTurn()` 里、**DoT 之后**（产品要求"优先级最低"）：
  中毒/点燃把血打到债务线以下，债务当场收人；反过来先判债务，那口毒就白下了。
- 不衰减、不挡护甲、不会被「抵挡」抵消。终结牌「终末清算」的清算**无视护甲与虚血**。
- 特效：`view.onDebtExecute(list)` —— 暗屏 1 秒 + 每只怪一道白色刀光 + 「终结」字样；
  多只同时被终结时**只暗屏一次**。

### 遭遇战强度：单体递增 + 每层合计封顶

2026-10-17 玩家反馈"第 1 层开局遇到两只吸血蝙蝠（4×2 各一发 = 16/回合），
比该层 Boss 还狠"。根因不是某只怪的数值，而是**层内梯度只有一条水平线**。

现在有两条硬约束（测试 `AM` 段守着）：

| 约束 | 规则 |
|---|---|
| 单体递增 | 同层 weak ≤ strong ≤ elite ≤ boss 的"单只怪最重一击"必须递增 |
| 合计封顶 | 一个遭遇里所有怪同时打最重一招的总和 ≤ `ENCOUNTER_DMG_CAP[层]`（14 / 24 / 34 / 44） |

另外加了一层**层内渐进**（`battle.js` 的 `innerScale`）：按地图纵向位置 `progress`
把敌人整体缩放 ×0.92 ~ ×1.08，**居中映射**——层中正好 ×1.00，
所以层平均值不变、产品定的那份伤害档位表仍然成立，只是地图前半段确实变轻了。
`progress` 由 `main.js` 的 `progressOf(node, kind)` 从节点行号算出（Boss 固定 1.0），
并写进战斗快照。

> ⚠️ 改遭遇表后**必须重跑** `tools/enemy-damage-report.mjs` 与测试 `AM` 段 ——
> 手算很容易差 1~2 点（我自己连续错了三轮才凑齐）。

**⚠️ 验证 `startBlock` 类效果时的坑**：`playerTurn()` 开头会**清空护甲**（除非有「壁垒」），
而 `battle.start()` 给的甲是在**这一回合开始前**加的 —— 所以战斗跑起来之后再读
`B.player.block` 往往是 **0**，看着像"遗物没生效"，其实它生效过。
判断办法：挂一个 `view.onBlock` 记下开局给过的点数，别在回合开始后读状态。
（实测踩过一次：以为「日冕护目镜 +8 护甲」坏了，其实是清甲的正常行为。）

**自定义钩子遗物**（如「钉刺长靴」用 `kill`、「黄铜指虎」用 `battleStart`）：
钩子方法只能调 `battle.js` 里**已存在**的方法，且要注意时机 ——
`battleStart` 在首回合抽牌**之前**，`turnStart` 在抽牌**之后**。

**新增遗物的定值规矩**：不要做出同类普通遗物的"加强版"（否则拿到它就等于拿到更好的那件）。
R3 段断言会拦：`startBlock > 6` / `startThorns > 3` / `startHeal > 3` / `startStrength > 1` /
`startDexterity > 1` 且**没有代价**（`maxHp<0` / `drawPerTurn<0` / `potionSlots<0` / `startLoseHp`）就会红。

### (d) 加一个随机事件 —— `js/data/events.js`

必填：`id` · `name` · `text` · `options[]`，每项 `{ label, desc?, req?(G), run(G, api) }`；`art` 可省（默认 gargoyle）。总数需 ≥ 10。

`api` 提供 `heal/damage/maxHp/gold/addRelic/addPotion/addCard/addCurse/randomRelic/randomCard/removeCard/upgradeCard/transformCard/upgradeBasics/fightElite/rng`。
**注意**：`removeCard` / `upgradeCard` / `transformCard` 返回 Promise，`run` 里必须 `await`/`return`，否则会在玩家选完之前就继续往下走。

### (d2) 每层的开场事件 —— 同一个文件的 `ACT_INTROS`

除了路上随机遇到的 `EVENTS`，**每一层开始时**还会先过一个开场事件
（类似《杀戮尖塔》的 Neow）：选项互斥、只能选一次，选完才开始探索这一层。

```js
{ id: 'intro_3', act: 3, name: '深渊回廊', art: 'gargoyle',
  text: '……',
  options: [
    { label: '在石板上磨砺', desc: '升级一张卡牌', run: (G, api) => api.upgradeCard() },
    // 需要连做两次的，用 async/await（api 里那三个 Promise 方法）
    // run: async (G, api) => { await api.upgradeCard(); await api.upgradeCard(); }
  ] }
```

**接入点（改流程时别漏）**：
- `main.js` 的 `startRun()` 与 `afterRoom()`（打完 Boss 进下一层时）都走 `goIntro()`
- `go()` 里 **`'intro'` 是独立分支**，`onDone` 绑 `afterIntro`（直接回地图）；
  普通 `'event'` 的 `onDone` 是 `afterRoom`（会判断"是不是 Boss 房间"）—— 两者不能混用
- 续战：`resumeRun()` 要认 `scene: 'intro'`，否则中途关页面回来会跳过开场事件
- `R5` 段断言盯着：四层各有一个、结构完整、**不能混进普通 `EVENTS` 池**

### (d3) 加一条难度规则 / 增益 —— `js/data/difficulty.js`

**难度系统复用遗物那一套 `mods` / `hooks`**，所以加一条通常不用碰引擎：

```js
// 难度（+9 分）
{ id: 'd_xxx', name: '名字', desc: '描述（支持 <b>HTML</b>）',
  mods: { someKey: 1 } }          // 静态修正
// 或
{ id: 'd_yyy', name: '名字', desc: '…',
  hooks: { enemyActed(B, e) { B.add(e, 'strength', 1); } } }   // 事件钩子
```

**接入点（按效果落在哪一层选）**：

| 想做的事 | 放哪 | 例子 |
|---|---|---|
| 战斗内数值/起手状态/每回合 | `core/battle.js` 里读 `this.mods.<k>` | `enemyHpPerAct` / `bossHpMult` / `summonWeak` |
| 商店 / 营火 | `ui/scene-rooms.js` 里读 `relicMods().<k>` | `shopPriceMult` / `restHealMult` |
| 地图生成 | `core/map.js` 的 `generateMap(seed, act, opts)` | `eliteWeightUp` / `restAsEvent` |
| 房间路由 | `main.js` 的 `enterRoom` / `mapOpts()` | `restAsEvent` 兜底 |
| 事件钩子 | 只需在 `difficulty.js` 写 `hooks`，引擎已会调用 | `enemyActed` / `powerPlayed` / `battleWin` |

**已有钩子名**：`battleStart` `turnStart` `turnEnd` `cardPlayed` `powerPlayed` `kill`
`enemyActed` `summoned` `battleWin`。加新钩子名时**必须在引擎里真的调用它**，
否则规则会静默失效（`W4` 段的测试就是为此而写 —— 它**真跑一轮战斗**，
不是手动调钩子函数）。

**⚠️ 三个必须知道的坑**（都踩过）：

1. **`relicHooks()` 返回三元组 `[id, fn, def]`**，第三个元素是定义对象。
   调用点要用 `def`，**不能用 `RELICS[id]`** —— 难度条目不在 `RELICS` 里，
   那样会拿到 `undefined`（我之前把所有调用点写的是 `RELICS[id]`，靠改这里才通）。
2. **开局一次性效果必须用 `pickMods()`，不能用 `relicMods()`** ——
   后者含遗物，而遗物的 `maxHp`/`potionSlots` 已经在 `addRelic()` 里生效过一次，
   再套一遍就是重复叠加。`applyPickStartBonuses()` 里对此有断言。
3. **改了素材/代码后必须 `npm run build`**，否则 `sw.js` 版本号不变、
   测试跑的也还是旧 bundle（`V8` 段会拦住"忘记 build"）。

**测试**：`W` 段覆盖"逐条实际生效"（不是只查数据表），加新条目时照着补一条。
`W4` 用 `A.startRun(cls, picks)` 传参 —— ⚠️ 签名是 **`startRun(clsId, picks)` 两参**；
另外测试必须通过 `window.__ABYSS__` 拿函数，**不要 `import('js/core/state.js')`**：
那会创建**另一份模块实例**（有自己独立的 `G`，通常是 null），断言会静默失效。

### (e) 加一个「能点的小图标」—— 用 `bindTipAction`，别自己写 click

`js/ui/widgets.js` 提供两段式点击：

```js
bindTipAction(node, {
  html: () => `<div class="tname">${p.name}</div>${p.text}`,  // 说明（字符串或函数）
  hint: '再点一次使用',        // 第二次点击前的提示；不传 onAction 时整段提示不显示
  onAction: () => usePotion(i), // 不传 = 只查看（遗物、地图上的药水）
  sceneNode: root,              // 传了就能在切场景时自动收起气泡
});
```

**约定**：
- 需要"确认才生效"的动作**一律用两段式**，不要 `node.addEventListener('click', …)` 直接执行 ——
  手机上没有 hover，误触代价是实打实的（曾把药水做成单击即喝，点错就浪费一瓶）。
- **`sceneNode` 一定要传**：气泡挂在 `body` 上（为了不参与 `#zoom` 缩放），
  **不会**随 `clear(#app)` 一起消失，不登记收尾就会在切场景后留在屏幕上。
- 元素需要"已点开、等确认"的视觉反馈时，加 `class="armed"`（CSS 已有金色呼吸边框）。
- 同时只会有一个图标处于待确认状态（`arm()` 里会先 `disarmTipAction()`），5 秒无操作自动收起。
- 动态重建的列表（药水条）**记得在重建前调 `disarmTipAction()`**，
  否则旧节点被 `clear()` 掉了、气泡还指着它。

## 5. 立绘与素材

- **不是图集**：63 个独立的 16×16 PNG，与 `sprites.json` 的 63 个键一一对应。
- `SPR(name)` → `asset('assets/sprites/' + name + '.png')`。`asset()` 在**单文件版**里改成查 `window.__ASSET_MAP__` 拿 data URI。
- `sprites.json` 的值**运行期无人读取**，只有测试拿 `Object.keys` 当白名单 →
  **只加 json 不加 PNG 也能过测试，运行时才 404 变空白**。加图时两边都要动。
- `assets/ui/`（边框、血条、按钮）走 CSS `url()`，是另一套，不经 `SPR`。

### ⚠️ 发版必看：SW 版本号怎么算（2026-10-12 修过一次真事故）

`sw.js` 的 `VERSION` 由 `npm run build` 按**内容哈希**自动盖戳。浏览器只在
`sw.js` **字节变化**时才重新 install，install 才会重新预缓存 → **版本号不变，用户就永远看旧资源**。

**踩过的事故**：Boss 立绘从 308B 重画成 128B、部署上线、线上 PNG 确实换了，
但版本号没变 → 浏览器不重新预缓存 → **用户看到的还是旧贴图**（"改了好像没变化"）。
根因是旧算法只喂了 `precache.json`，而**那里面只有文件名列表、没有任何内容哈希**：
**只改素材内容（不改文件名）时哈希不变。**

现在哈希输入 = **每一个预缓存资源的内容**（按码位序）+ `precache.json` / `index.html` /
`css` / `manifest` / `dist/bundle.js` + `sw.js` 自身（剔掉 VERSION 行，避免自指）。

**所以改了任何素材/代码后，必须 `npm run build` 再提交** ——
忘了 build，`V8` 段断言会红（它独立重算一遍哈希，并抓"手改 VERSION"与"忘记 build"两种情况）。

> 两个陷阱：
> 1. **测试与 build 不能共用同一个函数** —— 那样两边一起错就测不出来。
>    `V8` 是照同一口径**独立重算**的。
> 2. 别把哈希写成只喂文件名。`V8` 里有一条"自证"断言：改动一个图片字节，
>    重算的哈希必须变化 —— 它保证内容真的参与了哈希。

### 两种贴图来源（2026-10-12 起）

#### Boss 立绘原本的问题（**实测数据，不是印象**）

### ⚠️ 像素画"放大不糊"靠的是 `image-rendering`

2026-10-12 修了一个**存在很久但一直没被发现**的缺陷：
CSS 里那条 `img, .spr { image-rendering: pixelated }` **从未生效** ——
项目里根本没有 `.spr` 元素（贴图全靠 `background-image` 挂在 div 上）。
实测全站 10 个贴图元素 `image-rendering` 全是 `auto`，16×16 贴图被平滑插值糊掉。

现在改成全局 `*{image-rendering:pixelated}`（本游戏没有需要平滑插值的位图）。
**回归靠 `V6` 段的选择器覆盖分析** —— 它会在有人把规则退回 `img, .spr` 时变红。

> 两个已经踩过的坑：
> 1. jsdom **不支持** `image-rendering`（`getComputedStyle` 恒返回 `""`，而 `color` 正常），
>    所以元素级验证只能在真浏览器做，别在 jsdom 里写这条断言。
> 2. 解析 CSS 选择器前**必须剥掉注释**：我第一版没剥，`sel.includes('*')` 匹配到了
>    注释里的 markdown 星号（`**重点**`），把失效版本也当成了"全局规则"而放行。

| 26 | **读档续战会丢掉难度的攻击缩放（白捡便宜）** | `applySnapshot()` 里写的是 `enemyScale(this.act)`，而 `spawn()` 是 `enemyScale(this.act, this.mods)` —— 漏了难度修正。于是开了「凶性渐长」（每层额外 +8% 攻击）的局，**只要中途关页面再回来，敌人攻击倍率就掉回裸曲线**；而且意图预告会跟着一起变小，看起来完全正常，极难发现。回归测试 AI1 段直接比对"读档后的 `atkMult`"与"同层新开一场"的倍率。 |
| 27 | **读档续战会丢掉战斗内计数器** | `serialize()` 不存 `potionUsed/Count`、`killCount`、`cardsThisBattle`、`cardsThisTurn`，读回来全归零 → 炼金口袋的战后金币少给、磨砺之心的击杀进度清空、血契吊坠/连击护腕的计数错位。这些不影响"胜负"，但决定同一场战斗继续打的结果，属于必须如实还原的状态。回归测试 AI2 段（另有一条向后兼容断言：缺字段的老快照仍被接受）。 |

## 8. 发布流程

推 `main` → GitHub Actions 自动：**test → build → deploy 到 GitHub Pages**。

- 工作流：`.github/workflows/deploy.yml`
- 线上：<https://hbbb1666.github.io/abyss-deck/>
- 单文件版也会随构建产出，并作为 artifact 保留 90 天
- Pages 的 Source 必须设成 **GitHub Actions**（已在仓库里配好 `build_type: workflow`）

**站点目录 = 仓库根目录**，靠 `rsync` 排除 `node_modules/.git/.github/tools/_site/dist` 再补上 `dist/abyss-deck.html`。
`index.html` 走原生 ESM 直接加载 `js/main.js`，**不依赖 `dist/`**，所以这样组装的站点是完整的。

改完代码本地自查的最短路径：

```bash
npm run build && npm test        # 必须都绿
```

## 9. 协作约定（桌面端 + 手机端）

- **手机端不方便跑 npm**，所以「改代码 → build → test → 提交」这条链**以桌面端为准**。
- 改动前先 `git pull`；改动后必须本地 `npm run build && npm test` 全绿再推。
- 每次改完 `js/` 或数据，**必须重新 build 后再 test**（`dist/` 不在版本库里）。
- 新增素材 PNG 后，`precache.json` 也需要 build 才会刷新——测试 H 段会盯着这条。

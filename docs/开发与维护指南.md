# 开发与维护指南

> 这份文档是接手/改动本项目时的**第一入口**。README 面向玩家，这里面向改代码的人。
> 内容基于对源码的逐文件阅读 + 在本机真实跑通 `build` / `test` + 线上站点实机点测。
> 凡未能确认的推断都显式标注「未确认」，不要把推断当结论用。

---

## 0. 三分钟上手

```bash
npm ci                # 安装依赖（jsdom + rollup）
npm run build         # 必须：产出 dist/bundle.js 与 precache.json
npm test              # 222 项
npm run build:single  # 可选：产出 dist/abyss-deck.html（素材全内联）
npm run serve         # 本地起服务，手机同局域网可访问 http://<电脑IP>:8765
```

**顺序不能反**：`dist/` 是 `.gitignore` 的，`tools/test.mjs:50` 直接读 `dist/bundle.js`，
所以**没先 build 就 test 必然 ENOENT**。CI 里也踩过这个坑（见 §7）。

改了 `js/` 或数据文件后，**每次都要重新 `npm run build`**，否则测的还是旧产物。

## 1. 架构与数据流

```
data/  纯数据（无逻辑）      cards / enemies / relics / potions / events / classes
  ↓
core/  引擎（不碰 DOM）      battle(战斗) · state(全局状态+存档) · map(地图生成) · util · audio
  ↓
ui/    场景（无框架，直接操作 DOM）
                            main(路由) · scene-battle · scene-map · scene-rooms · scene-menu · widgets
```

**关键约定：`core/` 绝不 import `ui/`**。战斗引擎想跟界面说话，一律通过 `opts.view` 上的回调
（`battle.js` 里满是 `this.view.onDamage?.(...)`），所以引擎可以在 jsdom 里裸跑——测试正是这么做的。

场景切换只有一条路：`main.go(name, ...)`（`js/main.js:20`）。每个 `sceneXxx()` **同步返回一个 `.screen` 节点**，
`go()` 负责 `clear(#app)` → append → rAF 里 `fitAllCards()` → 非菜单类场景 `save()`。没有虚拟 DOM，没有 diff。

## 2. 一个回合到底发生了什么（改战斗必读）

顺序是**语义的一部分**，挪动任何一步都会改变游戏行为。

**`playerTurn()`**
1. `turn++`
2. **清空护甲**（除非有 `barricade` 壁垒）—— 注意：**在中毒之前**
3. 结算玩家中毒（无视护甲掉血）→ 层数 −1 → 判死
4. `berserk_dmg` 自伤 → 判死
5. 遗物钩子：`undying`/`block_next` 加甲、`ritual` 加力量
6. 回满能量（3 + 各种修正，首回合另有 `firstTurnEnergy`）
7. **手牌全部进弃牌堆** → 抽 5 张（+修正）
8. `turnStart` 遗物钩子 → `rollIntents()`（决定敌人下回合意图）→ 同步界面 → 存档

**`endTurn()`**
1. 手牌里 `endDmg` / `curse_regret` 的反噬伤害
2. 手牌进弃牌堆
3. `tickEnd(玩家)`：`vulnerable` / `weak` / `frail` 各 −1
4. `regen` 回血后 −1
5. `turnEnd` 遗物钩子 → 存档 → `checkOver()`
6. 进入 `enemyTurn()`

**`enemyTurn()`** 遍历**进入那一刻的存活快照**（所以当回合新召唤的小怪不行动）
1. `e.turn++` → 清空敌人护甲（同上，除非 barricade）
2. 结算敌人中毒 → 判死则跳过
3. 执行**已预定**的 `moveId`：护甲 → 伤害（含多段 `hits`）→ `selfDamage` → `fx`
4. `tickEnd(e)` → 同步 → 判玩家死 → `checkOver()`

全部敌人行动完 → `rollIntents()` 预定下一轮 → 回到 `playerTurn()`。

### 意图为何总是准的
`pickMove` 用 `e.turn + 1` 计算，`enemyTurn` 只读预先存好的 `moveId`。
**所以"敌人头顶显示的意图"和它实际做的事必然一致**——改 AI 时不要破坏这个两段式。

### 死亡与召唤
- `damage()` 内 hp ≤ 0 → `kill()`；玩家死 → `endBattle(false)`
- 敌人死 → 把 `summonedBy === 该敌人` 的小弟**一并杀死**（避免 Boss 与小弟同归于尽时卡住判定）
- 场上敌人上限 **4 个存活**

## 3. 效果 DSL

卡牌用声明式效果描述，由 `resolve()` 解释执行（`battle.js:264`），共 **16 种** `t`：

```
dmg(带 hits) · dmgAll · dmgBlock · dmgPoison · dmgPerHand
block · blockFromBlock · draw · energy · heal · loseHp
buff · debuff · debuffAll · gold · discard
```

```js
fx: [{ t: 'dmg', v: 'dmg', hits: 'hits' }]
```

`v` 可以是**数字**，也可以是**卡牌字段名的字符串**——结算那一刻才从卡实例上取值。

**升级（`up`）为什么不用改 `fx`**：`makeCard()` 用 `Object.assign(c, base.up)` 覆盖实例字段，
`fx` 里写的是字段名，所以数值自动跟着升级走。这是这套 DSL 最省事的地方，加卡时请保持这个风格。

**敌人的效果是另一套解析器**（`resolveEnemyFx`）：`buff / buffAll / debuff / healSelf / block / summon / addCard`。
**两套不通用**，别把玩家的 `t` 写进敌人 `moves`。

## 4. 加内容：确切的步骤

> 共同前提：立绘名必须**同时**满足 ①`assets/sprites/<名>.png` 存在 ②`assets/sprites.json` 里有同名键。
> 改完记得 `npm run build`（刷新 `precache.json`），否则测试 H 段会失败。

### (a) 加一张卡牌 —— `js/data/cards.js`

必填：`name` · `cls` · `type` · `rarity` · `cost` · `target` · `art` · `text(c)` · `fx[]`
可选：`up{}`（升级覆盖同名字段）· `exhaust` · `unplayable` · 以及被 `fx` 用字符串引用的数值字段

```js
my_card: {
  name: '裂空斩', cls: 'knight', type: 'attack', rarity: 'rare', cost: 2, target: 'enemy',
  art: 'sword_broad', dmg: 15, up: { dmg: 20 },
  text: c => `造成 <b>${c.dmg}</b> 点伤害。`,
  fx: [{ t: 'dmg', v: 'dmg' }],
},
```

**测试会挡住的**：`id` 必须等于键名；`text` 升级前后都不能为空；`fx` 里字符串值必须是卡上真实字段；
`art` 必须在 `sprites.json`；卡牌总数 ≥ 50；**每个职业 × {common, uncommon, rare} 的奖励池 ≥ 3 张**。

**测试挡不住的坑**：造新的 `rarity` / `type` 字符串不会报错，但 `RARITY` / `TYPE_LABEL` 查不到 →
边框静默回退成 common、类型标签变空白。

**文案长度红线**：卡面字号从 10.5px 逐档降到 8.5px，再放不下就**直接裁字**。
实测现有 130 条文案最长 27 字、均值 15.3。**≤ 27 字安全**，30–36 字需要实机确认，> 36 字基本会裁。
`.ctext` 里必须包一层 `.ctext-in`；带 `<b>` 的 HTML 直接塞进 flex 容器会把文字拆行、卡高爆掉（源码有警告注释）。

### (b) 加一种敌人 —— `js/data/enemies.js`

必填：`name` · `sprite` · `hp:[min,max]` · `act` · `moves{...}`，外加 `ai(e,turn,rng,B)` 或 `pattern`
可选：`elite` · `boss` · `body`（体型倍率）· `tint`（CSS filter）

`act` 只是**这套数值的基线层**，不代表它只能在那层出现 —— 整张敌人表被所有层复用，
出场强度由 `actScale(层)` 再乘一遍（**每层 +25% 生命、+20% 攻击**，相对第 1 层）。
所以：给第 4 层写新敌人时，数值要**照第 4 层的量级**给（它会再吃 1.6 倍攻击）。

**最容易被漏掉的一步**：敌人必须**手动**登记进 `ENCOUNTERS[act]` 的 `weak/strong/elite/boss` 里，
否则它**永远不会出现，而且测试不报错**（测试会核对"表里引用的 id 都存在"，
但不会核对"每个敌人都被用上"）。

**加层数**：改 `enemies.js` 的 `TOTAL_ACTS` 并补上 `ENCOUNTERS[TOTAL_ACTS]`。
`main.js` 的 `pickEncounter` / `afterRoom` 都读这个常量，不会再出现"第 4 层取不到遭遇战表"。
测试硬编码了 `TOTAL_ACTS === 4`，改层数时它会提醒你同步更新文档。

### (c) 加一件遗物 —— `js/data/relics.js`

必填：`name` · `sprite` · `rarity` · `desc`（字符串）+ `mods{}` 或 `hooks{}`

`mods` 的键必须被引擎真正读取（`maxHp` / `energyPerTurn` / `startBlock` / `shopDiscount` / `battleGold` …）。
**这条没有测试保护**——写错键名 = 遗物静默无效。`hooks` 里的方法名有测试核对（必须存在于 `battle.js`）。

### (d) 加一个随机事件 —— `js/data/events.js`

必填：`id` · `name` · `text` · `options[]`，每项 `{ label, desc?, req?(G), run(G, api) }`；`art` 可省（默认 gargoyle）。
总数需 ≥ 10。

`api` 提供 `heal/damage/maxHp/gold/addRelic/addPotion/addCard/addCurse/randomRelic/randomCard/removeCard/upgradeCard/transformCard/upgradeBasics/fightElite/rng`。
**注意**：`removeCard` / `upgradeCard` / `transformCard` 返回 Promise，`run` 里必须 `await`/`return`，否则会在玩家选完之前就继续往下走。

### (e) 加一个「能点的小图标」—— 用 `bindTipAction`，别自己写 click

`js/ui/widgets.js` 提供两段式点击：

```js
bindTipAction(node, {
  html: () => `<div class="tname">${p.name}</div>${p.text}`,  // 说明（字符串或函数）
  hint: '再点一次使用',        // 第二次点击前的提示；不传 onAction 时整段提示不显示
  onAction: () => usePotion(i), // 不传 = 只查看（遗物、地图上的药水）
  sceneNode: root,              // 传了就能在切场景时自动收起气泡
});
```

**约定**：
- 需要"确认才生效"的动作**一律用两段式**，不要 `node.addEventListener('click', …)` 直接执行 ——
  手机上没有 hover，误触代价是实打实的（曾把药水做成单击即喝，点错就浪费一瓶）。
- **`sceneNode` 一定要传**：气泡挂在 `body` 上（为了不参与 `#zoom` 缩放），
  **不会**随 `clear(#app)` 一起消失，不登记收尾就会在切场景后留在屏幕上。
- 元素需要"已点开、等确认"的视觉反馈时，加 `class="armed"`（CSS 已有金色呼吸边框）。
- 同时只会有一个图标处于待确认状态（`arm()` 里会先 `disarmTipAction()`），5 秒无操作自动收起。
- 动态重建的列表（药水条）**记得在重建前调 `disarmTipAction()`**，
  否则旧节点被 `clear()` 掉了、气泡还指着它。

## 5. 立绘与素材

- **不是图集**：62 个独立的 16×16 PNG，与 `sprites.json` 的 62 个键一一对应。
- `SPR(name)` → `asset('assets/sprites/' + name + '.png')`。`asset()` 在**单文件版**里改成查 `window.__ASSET_MAP__` 拿 data URI。
- `sprites.json` 的值（`[col,row]`）**运行期无人读取**，只有测试拿 `Object.keys` 当白名单 →
  **只加 json 不加 PNG 也能过测试，运行时才 404 变空白**。加图时两边都要动。
- `assets/ui/`（边框、血条、按钮）走 CSS `url()`，是另一套，不经 `SPR`。

## 6. 存档

- 存档 key：`abyss_deck_save_v1`；跨局统计：`abyss_deck_meta_v1`
- 战斗中每 **900ms 节流**存一次，另外 `afterAction()`（每次出牌后）强制落盘，
  并有 `beforeunload` / `visibilitychange` / `pagehide` 三重兜底。
  **新增的状态变更如果没走 `afterAction`，就有丢失风险。**
- 战斗快照 `G.pending.snap` 是纯数据（`v: 1`），经 `resumeBattle()` 用 `new Battle([], { restore })` 复原。

**读档后必须重算的东西**（写在新逻辑里时别忘）：
1. RNG：`makeRng(seed)` 后 `setState(rngState)`
2. `map.byRow` 要**按 nodes 重新分组**，让两边引用同一批对象
3. 敌人 `uid` 每次读档都重新分配，所以快照里 `summonedBy` **存的是下标**，读档时再按下标接回

历史上的坑：`layout()` 曾用对象引用找节点，读档后 52 个节点全跑到屏幕外。现已改为按 `(r,c)` `findIndex`。
另外有一处 ad-hoc 迁移：旧档缺 Boss 节点会就地补一个。**没有通用版本迁移机制**。

| 17 | **地图会卡死进度（最严重的一个）** | `generateMap` 的路径游走写的是 `for (r = 1; r < MAP_ROWS; r++)`，于是在**最后一行**（Boss 行）也会生成普通节点。这一行之后没有行了，这些节点**没有任何后继** —— 玩家一旦从倒数第二行走进去就永远出不来，整局卡住；而且它们不是 Boss，所以也进不了下一层。实测：**300/300 张地图**都有这个问题，累计 753 个死路。修法：路径与补漏都只走到 `TOP_ROW`（倒数第二行），Boss 行由第 5 步独占；另外加了"任何非 Boss 节点都必须有出边"的兜底与断言。 |
| 18 | **只有 3 层，第 4 层不存在** | 原来 `main.js` 写死 `Math.min(G.act, 3)` 与 `G.act >= 3`，敌人表也只有 1–3 层。现在扩到 **4 层**（`TOTAL_ACTS = 4`）并补了第 4 层专属遭遇战表与最终 Boss「深渊之眼」。 |
| 19 | **敌人不随层数变强** | 整张敌人表被所有层复用，但强度完全一样 → 第 3 层和第 1 层打起来手感相同。现在 `actScale(层)` 统一缩放：**每层 +25% 生命、+20% 攻击**（相对第 1 层），第 4 层相当于 1.75 倍血 / 1.6 倍伤。缩放只作用在敌人自身属性上，玩家给的易伤/虚弱照常生效；`intentOf()` 与实际结算**共用同一个 `calcDamage`**，所以界面预告永远不会与实际伤害分叉（有断言跨 4 层 × 5 种状态组合盯着）。 |
| 13 | **`precache.json` 的顺序随文件系统变化 → SW 版本哈希不可复现** | `walk()` 按 `readdir` 顺序追加，而 NTFS 大致按名字、ext4 是哈希序。桌面端对证线上与本地的清单：**集合完全相同（149 项）、只有顺序不同**（线上 `grave_cross` 在 `gravestone` 前，NTFS 反之）→ 字节不同 → 哈希不同。手机端原先归因于"rollup 版本不一致"，实测锁文件与实装**都是 4.64.5**，归因是错的。改用 `sortedWalk()`（码位序）+ H 段断言盯住顺序；`buildAssetMap()` 同样改有序。 |
| 14 | **调试代理被发布到线上，且预缓存清单仍引用它** | 手机端审计发现线上 `/js/dev-agent.js` 返回 200，于是把它从站点排除（`index.html` 不写死 → `server.mjs` 动态注入 → workflow rsync 排除）。**但漏了 `buildPrecache()` 的黑名单** → `precache.json` 仍含它 → 线上 SW 安装时请求 404。桌面端用真实站点组装语义复现并修复：新增 `PRECACHE_SKIP_DEV_ONLY`，并把「build 排除 / workflow 排除 / index.html 不写死」三处绑成一条断言（三处各造一次错都验证过会红）。 |
| 20 | **遗物只能长按看说明；药水单击就误喝** | 遗物原本只绑了 `bindTip`（长按 420ms 才弹气泡），很多玩家根本不知道能按；而战斗中药水是 `click → usePotion`，**点错一下就浪费一瓶**。现在统一成两段式 `bindTipAction()`：第一下弹说明、第二下才执行。不传 `onAction` 时退化成"点一下看说明"（遗物、地图上的药水）。 |
| 21 | **药水从 0 瓶变 1 瓶时图标不刷新** | `sync()` 里的重建条件是 `potionBar.childElementCount !== Math.max(1, G.potions.length)`。空态会往药水条里塞一句「（没有药水）」，于是 **0 瓶和 1 瓶的 childElementCount 都是 1**（`Math.max(1,1) === 1`）→ 从 0 变 1 时**不重建**，新拿到的药水不显示。改成记录「上一次渲染的数量」（`potionsDrawn`）再比较。 |

## 8. 发布流程

推 `main` → GitHub Actions 自动：**test → build → deploy 到 GitHub Pages**。

- 工作流：`.github/workflows/deploy.yml`
- 线上：<https://hbbb1666.github.io/abyss-deck/>
- 单文件版也会随构建产出，并作为 artifact 保留 90 天
- Pages 的 Source 必须设成 **GitHub Actions**（已在仓库里配好 `build_type: workflow`）

**站点目录 = 仓库根目录**，靠 `rsync` 排除 `node_modules/.git/.github/tools/_site/dist` 再补上 `dist/abyss-deck.html`。
`index.html` 走原生 ESM 直接加载 `js/main.js`，**不依赖 `dist/`**，所以这样组装的站点是完整的。

改完代码本地自查的最短路径：

```bash
npm run build && npm test        # 必须都绿
```

## 9. 协作约定（桌面端 + 手机端）

- **手机端不方便跑 npm**，所以「改代码 → build → test → 提交」这条链**以桌面端为准**。
- 改动前先 `git pull`；改动后必须本地 `npm run build && npm test` 全绿再推。
- 每次改完 `js/` 或数据，**必须重新 build 后再 test**（`dist/` 不在版本库里）。
- 新增素材 PNG 后，`precache.json` 也需要 build 才会刷新——测试 H 段会盯着这条。
